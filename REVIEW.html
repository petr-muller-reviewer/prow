Verdict

Approve

Correct, minimal, well-targeted one-line fix for a real regression (introduced in #716), confirmed against the PushToCentral implementation and matching the explicit-refspec approach requested in review comments. Only gap is the lack of a regression test for this call site, which is not blocking given the change's small size and that it is already reviewed and merged.

What this PR does

  • processGitHubAppAuth commits changes on whatever branch is checked out (usually main) but then pushed by passing o.HeadBranchName (default autobump) straight to PushToCentral as if it were a local branch name.
  • No local branch called autobump is ever created, so git failed with error: src refspec autobump does not match any.
  • Fix changes the call to PushToCentral("HEAD:"+o.HeadBranchName, true), producing git push <remote> HEAD:autobump — pushes the current commit under the current HEAD, independent of the local branch's actual name.
  • Scope is exactly one line changed in cmd/generic-autobumper/bumper/bumper.go.

Things I checked and was fine with

  • PushToCentral's implementation (pkg/git/v2/publisher.go:96) appends its branch argument verbatim to git push <remote> <branch>, so "HEAD:"+o.HeadBranchName is a valid, standard git refspec — the fix is correct.
  • Other uses of o.HeadBranchName, e.g. the MinimalGitPush call at bumper.go:297 (fork-based push path), are unaffected — that path checks out/creates the branch locally before pushing.
  • No security implications: only the push refspec target changed, no credential handling touched.
