Verdict: request changes

The normalization and fixed state ordering improve the job bar, but the 1%-minimum width clamp makes sparse states inaccurate and can make the bar exceed 100% total width. This contradicts the PR's stated goal of rendering actual count percentages.

What this PR does

  • Normalizes missing and unrecognized ProwJob states into an unknown job-bar segment.
  • Renders supported states in a fixed order rather than sizing one final state with auto.
  • Adds scheduling to the Deck ProwJob state type and job bar.
  • Adds markup and color styling for the scheduling segment.

Findings

Blocking

Blocking — Sparse job-bar segments are not proportional
cmd/deck/static/prow/prow.ts:827-830

el.textContent = count.toString();
tt.textContent = \`${count} ${stateToAdj(state)} jobs\`;
el.style.width = \`${Math.max((count / total * 100), 1)  }%\`;

Math.max(count / total * 100, 1) makes every nonzero state smaller than 1% occupy 1% of the bar. Multiple sparse states can therefore exceed 100% total width, contradicting the actual-count-percentage goal. Remove the clamp, or use a separate affordance for tiny counts that does not alter bar widths.
