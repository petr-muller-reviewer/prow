Verdict

Approve

This is a well-reasoned, test-only fix for a genuine happens-before bug in the test itself (not the reloader). The new synchronization point (reloadCensor) is provably correct because it runs only after the value store under lock, and the rewritten bad-parse assertion replaces an unprovable "never observed" check with a waitable ordering guarantee. No production code changes, no behavior regressions in coverage — the split-out TestAddWithParserRegistersSecret restores the public-API assertions that the timing rewrite gave up.

What this PR does

  • Fixes a flaky TestAddWithParser failure (expected value 2 from generator, got 1) that has intermittently failed the race-detector job since January.
  • Root cause: the test synchronized on the user parser callback, which runs at reloader.go:72 — before the parsed value is stored at reloader.go:80 — so there was no happens-before edge guaranteeing the getter saw the new value.
  • Rewrites the test to synchronize on reloadCensor instead, which fires only after p.lock.Unlock() at both call sites (reloader.go:44, :82), giving a real happens-before edge per the Go memory model.
  • Replaces point-in-time getter sampling for the bad-parse case with an assertion on the ordered sequence of published values — a liveness property that can be waited on, with no sleeps or observation windows.
  • Adds TestAddWithParserRegistersSecret to recover synchronous public-API coverage that the timing-focused rewrite no longer exercises.

Findings

None. No blocking, should-fix, or nit issues found.

Things I checked and was fine with

  • reloadCensor call sites are exactly reloader.go:44 and :82, both after the lock releases — matches the PR's synchronization claim.
  • writeSecret's time.Now().Add(generation*time.Second) guarantees strictly increasing mtimes across generations, independent of filesystem timestamp granularity.
  • awaitPublish's repeat-skipping logic (got == last && got != want) correctly absorbs the one remaining benign race: a poll landing between os.WriteFile and os.Chtimes.
  • No exported API changed; nothing else in the tree depends on the old synchronization pattern.
  • The PR's claim of a synthetic-regression check (temporarily removing the continue at reloader.go:75) is consistent with how the rewritten assertions are structured — that scenario would indeed surface as a value mismatch in awaitPublish.

Open questions for the author

None — the PR description already explicitly flags the deferred time.Tick goroutine-leak and lastModTime zero-value quirks as known, deliberately out-of-scope warts.
