Verdict: request changes

The PR correctly identifies the root cause — /teams/{id}/members lacks the org, so GitHub Apps auth fails — and the rename to ListTeamMembersByID is a clean improvement. However, the replacement API path /orgs/{org}/team/{id}/members does not appear in GitHub's official REST API documentation (the documented ID-based alternate route is /organizations/{org_id}/team/{team_id}/members with numeric org ID, not org name). Additionally, callers like RerunAuthConfig.IsAuthorized can pass an empty org in periodic job contexts, which would produce a malformed path. Both issues should be addressed before merge.

What this PR does

  • Fixes GitHub Apps authentication failure when looking up team members by ID: the old API path /teams/{id}/members lacked the org, so extractOrgFromContext couldn't determine which installation token to use.
  • Changes the API path to /orgs/{org}/team/{id}/members, which includes the org for Apps auth compatibility.
  • Renames ListTeamMembers to ListTeamMembersByID and removes the deprecation warning, since the method is now a proper peer of ListTeamMembersBySlug rather than a deprecated shim.
  • Updates all callers across the TeamClient interface, fake client, milestone/milestonestatus/project plugins, and tests.
  • Cleans up the peribolos docs: fixes bullet style and updates the stale test-infra repo reference in an error message.

Findings

Blocking

Undocumented API path — pkg/github/client.go:3909

path := fmt.Sprintf("/orgs/%s/team/%d/members", org, id)

This path does not match any documented GitHub REST API endpoint. The documented patterns are:

  • /orgs/{org}/teams/{team_slug}/members — current, slug-based (plural teams)
  • /organizations/{org_id}/team/{team_id}/members — alternate route, numeric IDs (note: organizations not orgs, numeric org ID not name)
  • /teams/{team_id}/members — legacy, being deprecated

The PR's path mixes /orgs/{org_name} with singular /team/{numeric_id}. The author validated it with gh api, but GitHub could break this undocumented route without notice. Please verify this is officially supported or switch to a documented endpoint. If verified to work despite being undocumented, add a comment explaining how it was confirmed.

Empty org produces malformed URL — pkg/github/client.go:3909

path := fmt.Sprintf("/orgs/%s/team/%d/members", org, id)

Callers like RerunAuthConfig.IsAuthorized (in types.go:314) can pass an empty org in periodic job contexts — this is visible in the original stack trace where org is {0x0, 0x0}. The old path /teams/{id}/members didn't need org in the URL. The new path would produce /orgs//team/{id}/members. This was raised by reviewers alvaroaleman and matthyx in PR comments and remains unaddressed. Add a guard (return a clear error) or fall back to the legacy path when org is empty.

Update (2026-07-26): matthyx proposed a concrete path forward on the issue thread — keep GitHubTeamIDs working via this PR's org-scoped route with a hard error when org is empty, log a deprecation warning, document github_team_slugs as the replacement, and drop the field in a future major. upodroid is weighing this against outright removing github_team_ids. Still unresolved/unimplemented.

org omitted from duration log — pkg/github/client.go:3903

Inconsistent Accept headers — pkg/github/client.go:3917

ListTeamMembersByID uses application/vnd.github+json while ListTeamMembersBySlug uses application/vnd.github.v3+json. Functionally equivalent but a papercut for anyone wondering if the difference is intentional.

Questions

Interface rename as breaking change for out-of-tree consumers

The TeamClient interface rename from ListTeamMembers to ListTeamMembersByID is a compile-time breaking change for any code outside this repo implementing the interface. This is manageable (caught at build time, not runtime), but should it be documented in release notes? Or is a backward-compatible wrapper worth adding?
