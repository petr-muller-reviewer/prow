Request changes

This dependency bump does not build. CI is red on all three Go jobs (unit test, race-detector, verify-lint) with genuine compile failures caused by API removals in the bumped versions of k8s.io/apimachinery and sigs.k8s.io/controller-runtime — not flakes. It needs accompanying code fixes before it can land, which is unusual for a dependabot group bump and means this can't be treated as a rubber-stamp merge.

What this PR does

  • Bumps the root go.mod "kubernetes" dependabot group: k8s.io/api, k8s.io/apimachinery, k8s.io/client-go v0.33.11 → v0.36.3, k8s.io/utils pseudo-version, and sigs.k8s.io/controller-runtime v0.21.0 → v0.24.1.
  • Bumps hack/tools/go.mod: k8s.io/code-generator v0.32.8 → v0.36.3 and sigs.k8s.io/controller-tools v0.17.3 → v0.21.0.
  • Pulls a large tail of indirect dependency churn consistent with these major version jumps (structured-merge-diff v4→v6, kube-openapi, klog, gnostic-models, etc.).
  • Touches only manifest/lockfile content — no project source is changed by the PR itself.

  • No project code changed outside dependency manifests — genuinely dep-only, no separate code review needed for the diff itself.
  • No usage of controller-runtime's webhook Validator/Defaulter signature change (0.23) or GetEventRecorderFor events-API migration in the tree — those breaking changes don't add further blast radius beyond the FakeInformer issue above.
  • sigs.k8s.io/controller-runtime v0.24.1 (2026-05-11) and sigs.k8s.io/controller-tools v0.21.0 (2026-05-06) are ~11 weeks old — fine on freshness.
  • k8s.io/utils bump is a pseudo-version (untagged commit, 2026-02-10) — normal for that module, not a provenance concern.
  • Import surface confirmed heavy/core for all root direct deps (client-go 76 files, controller-runtime 54 files, apimachinery 276 files) — consistent with how broadly the breakage landed.
