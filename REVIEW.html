Verdict

Request changes

The PR is a tiny, docs-only change (one commit, four lines added to announcements.md), but its central factual claim — that transfer-issue has been consolidated into issue-management — does not match the current state of the codebase. Publishing it as written would tell users to remove a plugin they still need.

What this PR does

  • Adds a single dated bullet to the "New features" announcements list in site/content/en/docs/announcements.md.
  • Announces that transfer-issue has been folded into a new issue-management plugin, together with /link-issue, /unlink-issue, /pin-issue, and /unpin-issue.
  • Instructs operators to replace transfer-issue with issue-management in their plugins.yaml.
  • References PR #702 in the commit message as the source of the underlying change.

Findings

BlockingAnnouncement claims a consolidation that has not happened in code

site/content/en/docs/announcements.md:12-15

- *August 11, 2026* The `transfer-issue` plugin has been consolidated into the new `issue-management`
    plugin along with `/link-issue`, `/unlink-issue`, `/pin-issue`, and `/unpin-issue` commands.
    Users should replace `transfer-issue` with `issue-management` in their `plugins.yaml`.
    Both `/transfer-issue <repo>` and the shorter `/transfer <repo>` are supported.

pkg/plugins/transfer-issue/transfer-issue.go still defines pluginName = "transfer-issue" and registers its own generic comment handler. It's still imported separately in cmd/hook/plugin-imports/plugin-imports.go (line 66) alongside issue-management (line 41). pkg/plugins/issue-management/ has no transfer-related code at all. A user who follows this announcement and swaps transfer-issue for issue-management in plugins.yaml loses /transfer-issue and /transfer entirely.

Things I checked and was fine with

  • /link-issue, /unlink-issue, /pin-issue, /unpin-issue genuinely exist in issue-management — that part of the announcement is accurate.
  • Confirmed via grep that issue-management package has zero occurrences of "transfer".
  • Confirmed both plugins are still separately registered in the plugin-imports file.
  • Change surface is minimal and low-risk mechanically (pure doc addition, no code touched).

Open questions for the author

  • Is there a follow-up PR (the commit message references #702) that actually merges transfer-issue into issue-management? If so, should this announcement wait until that lands, or be merged together with it?
  • If the consolidation is planned but not yet done, should the wording move from past tense ("has been consolidated") to a forward-looking notice, so operators don't act on it prematurely?
