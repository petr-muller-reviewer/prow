Head: aac8df64b8281e8830abf8a0e31339c6600f0c09 · Base: main · Reviewed: 2026-09-14T22:47:50Z

Verdict

Request changes. The change is focused and low-risk, but one existing per-PR exclusion path still cannot produce the explanatory Tide status promised by this PR.

What this PR does

  • Isolates a Tide context-policy setup failure to its affected PR instead of dropping the entire subpool.
  • Stores exclusion reasons while constructing a subpool.
  • Passes exclusions from raw subpools to the asynchronous status controller.
  • Publishes an error tide status with the reason, before recreating a failing context checker.

Findings

Blocking — Preserve the GetPresubmits exclusion reason

pkg/tide/tide.go:1717-1720

presubmitsForPull, err := c.provider.GetPresubmits(...)
if err != nil {
    log.WithError(err).Debug("Failed to get presubmits for PR, excluding from subpool")
    continue
}

A per-PR GetPresubmits error still removes the PR without calling excludePR. The status controller may invoke GetPresubmits again while rebuilding the context policy and fail before setting the promised explanatory tide status. Record the reason in sp.excluded and add an end-to-end status-path test.
