Add support for git cherry-pick -x style commit messages
Base: main · Head: 05052e23ba428d40595917f28f2236f488b5b3a5
Reviewed: 2026-09-23T12:48:17Z

Verdict

Request changes.

The new behavior is opt-in and failure recovery is careful, but it rejects otherwise valid patches with a line longer than the scanner's default 64 KiB limit. That turns a successful git am into a failed cherry-pick request without pushing the branch.

What this PR does

  • Adds an --add-original-commit-id flag, disabled by default.
  • Extracts original commit SHAs from the downloaded mbox patch.
  • Rewrites the newly applied commits to append (cherry picked from commit <sha>).
  • Aborts and restores the local repository if annotation fails before branch push.

Findings

Blocking

Blocking SHA extraction rejects valid long-line patches — cmd/external-plugins/cherrypicker/server.go:850-860

scanner := bufio.NewScanner(file)
for scanner.Scan() {
    line := scanner.Text()
    if matches := fromPattern.FindStringSubmatch(line); matches != nil {
        shas = append(shas, matches[1])
    }
}
if err := scanner.Err(); err != nil {
    return nil, fmt.Errorf("error reading patch file: %w", err)
}

bufio.Scanner limits a token to 64 KiB by default. Long generated, minified, or lockfile lines are valid in a GitHub patch, but make SHA extraction fail and prevent an enabled cherry-pick from being pushed. Use a reader without that limit or raise the buffer appropriately, and add a regression test with a line over 64 KiB.

Things I checked and was fine with

  • The option defaults to false, preserving existing behavior.
  • Rewrite failure aborts the rebase, resets the pre-rebase HEAD, and prevents push.
  • Commit messages are passed through a temporary file rather than shell interpolation.
  • Focused tests cover empty input, invalid history, commit ordering, and rollback.

Open questions for the author

  • Can the follow-up add a handler-level test for an enabled multi-commit mbox patch, plus regression coverage for a patch line larger than 64 KiB?
  • Should the cherrypicker documentation describe the flag, its default-disabled rollout, and the changed commit hashes/messages when enabled?
