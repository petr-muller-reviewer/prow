What this PR does

  • Adds opt-in ignore_merge_commits config to the Owners config struct.
  • When enabled for a repo, the owners-label plugin calls ListPullRequestCommits on every PR open/reopen/synchronize and skips labeling if any commit has more than one parent (merge commit).
  • After a force-push removes the merge commit, the plugin re-fires on the synchronize event and applies correct labels.
  • Adds ListPullRequestCommits to the local githubClient interface (real and fake clients already implement it).
  • Adds TestHandleIgnoreMergeCommits covering both the skip and proceed paths.

Since previous review:

  • IgnoreMergeCommits changed from a global bool to a []string of org / org/repo entries (pkg/plugins/config.go:256-259), following the same shape as SkipCollaborators.
  • Added Configuration.IgnoreMergeCommitsFor(org, repo) (pkg/plugins/config.go:305-313), the same lookup pattern as SkipCollaborators.
  • handlePullRequest now calls pc.PluginConfig.IgnoreMergeCommitsFor(pre.Repo.Owner.Login, pre.Repo.Name) instead of reading the bool directly (pkg/plugins/owners-label/owners-label.go:69).
  • No code changes since 2026-07-26T22:39:28Z. Prucek left two new comments on 2026-08-10: generated docs are stale, and the org/repo membership-check loop should be factored out (see Findings).

Flagged by Prucek on 2026-08-10: the new ignore_merge_commits config field is not reflected in the generated documentation. make verify-codegen needs to be run and its output committed before merge, or CI's codegen-verify check will fail.

Should fix Merge commit API call runs before label-need check

pkg/plugins/owners-label/owners-label.go:77-88

ListPullRequestCommits executes before GetPullRequestChanges. When no OWNERS labels apply to the changed files, the function already early-exits at line 99 with the comment "Return now to save API tokens". With the current ordering, the commit-listing call is wasted in that case. Moving the label-need check (lines 90–102) before the merge commit check would avoid the extra API call on the common path where no labels apply. 

if ignoreMergeCommits {
    commits, err := ghc.ListPullRequestCommits(org, repo, number)
    // ...
}

// ... later, after GetPullRequestChanges:
if neededLabels.Len() == 0 {
    // No labels requested for the given files. Return now to save API tokens.
    return nil
}

Resolved

Resolved Config granularity: global bool vs per-org/repo — resolved in ddde196fe

pkg/plugins/config.go:256-259

Original concern: MDYAMLRepos, SkipCollaborators, and Filenames in the same Owners struct support per-org or per-repo configuration with corresponding lookup helpers. IgnoreMergeCommits was a single bool for the entire prow instance. A multi-tenant deployment could not enable this selectively. This concern was flagged independently by all three review perspectives, and reviewer Prucek raised the same point as an inline PR comment on 2026-07-02.

Resolution: IgnoreMergeCommits is now []string of org / org/repo entries, with IgnoreMergeCommitsFor(org, repo) resolving it the same way SkipCollaborators does. handlePullRequest was updated to call the new helper.

Nit Add comment on config field noting global scope — superseded in ddde196fe

pkg/plugins/config.go:256-259

Moot — the field is no longer global-only (see above). The doc comment on IgnoreMergeCommits was updated to describe the org/org-repo list format instead.
