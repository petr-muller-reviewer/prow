Verdict

Request changes

The core stripping/rewriting mechanism (normalizeBasePath / withBasePath / absolutePath) is sound in design, but the PR as shipped appears to break Deck entirely: base.html calls a template function (deckPathIfRelative) that is never registered in the FuncMap, and since base.html is parsed on every page render, this should fail template parsing for every installation — not just ones using the new --base-path flag. On top of that, only base.html's chrome was migrated to base-aware links; every other template and several frontend API calls still hardcode root-relative paths, so even after the parsing bug is fixed, enabling --base-path would 404 most of the app.

What this PR does

  • Adds a --base-path flag to Deck (cmd/deck/main.go) so it can be served from a sub-URL.
  • New cmd/deck/basepath.go: normalizeBasePath, withBasePath (an http.Handler wrapper that strips/rejects by prefix), and options.absolutePath/absolutePathIfRelative helpers.
  • Rewrites a subset of Spyglass/job-history/PR-history link fields to be base-aware via absolutePathIfRelative.
  • Extracts the HTTP→HTTPS redirect out of prodOnlyMain into a standalone withHTTPRedirect middleware, changing middleware ordering.
  • Adds deckBasePath/deckPath template funcs and new TS exports (deckURL, absoluteDeckURL) — wired into base.html only (and even there, a third function it calls, deckPathIfRelative, was never registered); the TS helpers are unused elsewhere.

Should fix

Should fixwithBasePath's RawPath handling can corrupt percent-encoded paths
cmd/deck/basepath.go, withBasePath closure (approx lines 49-61)

After stripping the base path prefix, r.URL.RawPath is set equal to the unescaped trimmed Path rather than being trimmed independently from the original RawPath. If the remainder contained percent-encoded characters (e.g. a Spyglass artifact key with an encoded %2F), this collapses the encoding, and EscapedPath() will subsequently mis-escape the path for downstream consumers. stdlib's http.StripPrefix trims RawPath independently for exactly this reason.

r.URL.Path = trimmed
if r.URL.RawPath != "" {
    r.URL.RawPath = trimmed
}
Should fixHTTP→HTTPS redirect middleware reordered as unrelated, undocumented scope creep
cmd/deck/main.go:507-519 (new handler chain), withHTTPRedirect

Previously the redirect wrapped the raw mux inside prodOnlyMain, running before traceHandler/CSRF. Now the chain is mux → withBasePath → traceHandler → CSRF → withHTTPRedirect, making the redirect outermost. Plausibly an improvement, but it also means 301 redirects for --redirect-http-to deployments are no longer observed by traceHandler, so they vanish from httpRequestDuration/httpResponseSize metrics — a quiet dashboard/alerting shift, not called out anywhere.

var handler http.Handler = mux
handler = withBasePath(o.basePath, handler)
handler = traceHandler(handler)
if csrfToken != nil {
    handler = CSRF(handler)
}
if o.redirectHTTPTo != "" {
    handler = withHTTPRedirect(handler, o.redirectHTTPTo)
}
Should fixNo unit tests for basepath.go's core logic
cmd/deck/basepath.go (whole file)

normalizeBasePath, stripBasePath, absolutePath, absolutePathIfRelative carry the most intricate, edge-case-prone new logic in the PR (trailing slashes, query/fragment splitting, prefix-vs-exact matching), yet there is no basepath_test.go. A table-driven test would have caught the RawPath issue above.

Should fixtraceHandler observes the unstripped path under a configured base path
cmd/deck/main.go:507-511 (handler chain ordering)

traceHandler's route simplifier was authored against unprefixed paths (e.g. /static, /tide). Since it runs outside withBasePath, it sees paths like /prow/static/... under a non-root base path, which will likely fall into a catch-all bucket instead of the expected route label — degrading per-endpoint metrics/tracing for base-path deployments.

Should fixHTTP→HTTPS redirect is no longer scoped to non-local runs
cmd/deck/main.go:517 (new unconditional withHTTPRedirect wiring in main())

Previously the redirect only applied inside prodOnlyMain, i.e. was skipped whenever runLocal was true. The refactor applies withHTTPRedirect in main() based solely on o.redirectHTTPTo != "", with no runLocal check. Running deck locally (e.g. with --pregenerated-data, so runLocal is true) while --redirect-http-to is also set would now redirect local requests carrying x-forwarded-proto: http to the configured host over HTTPS instead of serving them locally — a behavior change uncovered by any test.

Should fixabsolutePathIfRelative mishandles protocol-relative URLs, and this is reachable via config
cmd/deck/basepath.go, absolutePathIfRelative; reachable via Deck.Spyglass.PRHistLinkTemplate (cmd/deck/main.go:1103)

Any string starting with / is treated as relative and prefixed, including protocol-relative strings like //other-host/path. This is reachable in practice: an admin configuring PRHistLinkTemplate (or similar templated link fields) to a protocol-relative external URL gets it mangled into /prow//other-host/pr-history?..., turning an intended external/cross-host link into a broken same-origin path.

strings.HasPrefix(rel, "/")  // true for "//other-host/path" too

NitabsolutePath("/") returns basePath without a trailing slash
cmd/deck/basepath.go, absolutePath

o.absolutePath("/") returns o.basePath (e.g. /prow), not /prow/. Round-trips correctly with stripBasePath, but worth confirming it's intentional.

NitBase-path prefixing is bolted on ad hoc at each call site instead of centralized
cmd/deck/main.go (8+ call sites across handleConfiguredJobs, handleJobHistory, handlePRHistory, the spyglass lens-link builder, handleArtifactView)

Each handler individually calls o.absolutePathIfRelative/o.absolutePath on its own link fields rather than fixing link construction once at a shared point. Any new handler or link field added later must remember to wrap it, or it silently renders a base-path-unaware link — this is exactly how the spyglass.ts gap above happened.

NitPath/query splitting is hand-rolled and duplicated between Go and TS
cmd/deck/basepath.go (absolutePath, via strings.IndexAny(rel, "?#")), cmd/deck/static/common/urls.ts (splitPathAndSuffix)

Both implementations hand-roll the same path/suffix split instead of reusing net/url.Parse (already used elsewhere in main.go) or the URL API (already used one function above by relativeURL in the same TS file). Two independent hand-rolled parsers now need to stay in sync with each other and with edge cases the standard parsers already handle.

Things I checked and was fine with

  • normalizeBasePath correctly forces a leading slash and runs through path.Clean, preventing ..-based prefix escape.
  • csrf.Path(o.basePath) correctly scopes the CSRF cookie to the base path instead of hardcoding /.
  • withBasePath fails closed (404) on any request path not matching the configured prefix, rather than falling through to unprefixed routes.
  • stripBasePath prefix-matching correctly requires basePath + "/" (or exact match), so a sibling path like /prowfoo under base path /prow is not falsely accepted.
  • --base-path defaults to / in both gatherOptions and normalizeBasePath, and withBasePath is a true no-op at root — non-adopters should see no behavior change once the FuncMap bug is fixed.
  • License headers on new files match repo convention (Apache 2026 boilerplate).
