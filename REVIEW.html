Verdict

Approve

The change closes a real privilege-escalation path (a non-bot account whose username matched a configured trusted app was previously granted trust) and adds targeted regression tests. Already merged. A follow-up 3-perspective maintainer review (code quality, maintainability, deployment risk) independently corroborates this: all three verdicts agree the logic is correct and strictly more restrictive, with the only converging concern being a cosmetic formatting defect.

What this PR does

  • Fixes TrustedUser in pkg/plugins/trigger/trigger.go so the trusted_apps allowlist only matches usernames that genuinely end in [bot], instead of trusting any username that equals a configured trusted-app name once [bot] is (potentially no-op) trimmed.
  • Previously, strings.TrimSuffix(user, "[bot]") is a no-op when the suffix is absent, so a plain human/org account named e.g. github-app would be treated as trusted if github-app was configured in trusted_apps — bypassing collaborator/org-membership checks entirely.
  • Adds strings.HasSuffix(user, "[bot]") as a precondition before trimming and comparing.
  • Adds two unit tests: a non-suffixed username exactly matching a trusted app name (now correctly untrusted), and a username where [bot] appears but not as a trailing suffix (also correctly untrusted).
