Independent merge risk

Diff is confined to cmd/external-plugins/cherrypicker/ (main.go +23, server.go +110, server_test.go +236). No repo skill applies — the two overlaid skills are review/triage workflows, not compatibility checkers.

  • API: none. package main; no exported surface, no CRD, no proto, no config-file schema change.
  • Configuration: one new flag, --add-original-commit-id, defaulting true. Blast radius: every cherrypicker instance in every Prow deployment starts rewriting cherry-pick commit messages on upgrade with no opt-in. Not gated, not release-noted.
  • Behavioral: cherry-pick commit bodies change shape (trailer appended) for all users; --amend -m applies cleanup=whitespace, so bodies are additionally reflowed (trailing whitespace stripped, consecutive blank lines collapsed) — real git cherry-pick -x preserves them byte-for-byte (server.go:853).
  • Environment sensitivity: GIT_CONFIG_NOSYSTEM=1 only suppresses /etc/gitconfig; $HOME/.gitconfig still applies (server.go:878). commit.gpgsign=true breaks the in-script amend on every cherry-pick; rebase.autoSquash=true makes rebase -i reorder and squash any fixup!/squash! commit, so the cherry-pick PR would silently carry fewer commits than the source PR. Recommend GIT_CONFIG_GLOBAL=/dev/null.
  • Reliability: extractOriginalSHAs uses bufio.NewScanner with no Buffer() (server.go:810) — ErrTooLong on any patch line over 64 KiB (lockfiles, minified assets, base64 fixtures), silently disabling the trailer for those PRs. The rebase subprocess has no context timeout and runs while holding the per-org/repo lock.Lock(), so a wedged git stalls that repo's cherry-pick queue indefinitely (server.go:878). The 0755 temp script also fails on a noexec TMPDIR, and --exec shell-parses its path (server.go:872).

What this PR does

  • Adds --add-original-commit-id flag (default true) wired through main.go to a new Server.addOriginalCommitID field.
  • After git am applies the mbox patch, calls extractOriginalSHAs() to parse the patch file for From <40-char-sha> headers using a validated regex, then calls appendCherryPickMessages() to annotate each commit.
  • appendCherryPickMessages() resolves the pre-am base SHA via git rev-parse HEAD~N, generates a temporary shell script, and runs git rebase -i --exec with GIT_SEQUENCE_EDITOR=true to amend each commit message with (cherry picked from commit <sha>).
  • Adds five test functions: table-driven TestExtractOriginalSHAs (4 cases) and four TestAppendCherryPickMessages_* variants covering empty input, no-repo error, single commit, and multi-commit with ordering verification.
  • Replaces the original git filter-branch --msg-filter approach (deprecated, flagged by @stmcginnis in round 1) with git rebase -i --exec.

Findings

Blocking os/exec bypasses pkg/git/v2 abstraction layer
server.go:25, 796–833

Two raw exec.Command("git", ...) calls are added — one for git rev-parse HEAD~N and one for git rebase -i --exec. Every other git operation in this file goes through the Interactor interface (r.Am(), r.CheckoutNewBranch(), etc.) backed by pkg/git/v2/executor.go, which handles logging, credential censoring, and consistent error handling. These calls bypass all of that. The patch-modification approach would require zero additional git commands.

@stmcginnis gave /lgtm (Jun 5) without flagging this finding.

baseCmd := exec.Command("git", "-C", repoPath, "rev-parse", fmt.Sprintf("HEAD~%d", numCommits))
baseSHABytes, err := baseCmd.Output()
...
cmd := exec.Command("git", "-C", repoPath, "rebase", "-i", baseSHA, "--exec", tmpPath)
cmd.Env = append(os.Environ(), origEnv, "GIT_SEQUENCE_EDITOR=true", "GIT_CONFIG_NOSYSTEM=1")
Blocking Shell injection via unquoted variables in generated exec script
server.go:800–812

(1) $ORIGINAL_SHA unquoted in if [ -n $ORIGINAL_SHA ] — word-splits on whitespace. (2) $CURRENT_MSG unquoted in git commit --amend -m — a commit message containing backticks, $(), or double quotes executes as shell code under set -e. (3) baseSHA (from git rev-parse output) interpolated directly into the script body via fmt.Sprintf without validation — this is a different value from the ORIGINAL_SHAS env var that the SHA regex guards. Quoting "$ORIGINAL_SHA" and "$CURRENT_MSG" throughout would close most of this surface if staying with the rebase approach.

@stmcginnis gave /lgtm (Jun 5) without flagging this finding.

ORIGINAL_SHA=$(echo "$ORIGINAL_SHAS" | cut -d',' -f$COMMIT_NUM)
if [ -n $ORIGINAL_SHA ]; then
    CURRENT_MSG=$(git log -1 --pretty=%%B)
    git commit --amend -m "$CURRENT_MSG

(cherry picked from commit $ORIGINAL_SHA)"
fi

Question Would a pre-am patch modification approach be acceptable?

The mbox patch already contains From <sha> Mon Sep 17 00:00:00 2001 headers before r.Am() is called. Inserting (cherry picked from commit <sha>) before the diff --git separator in each commit section — pure Go string manipulation on a file already on disk — would eliminate both blocking findings: no os/exec, no shell script, no injection surface, trivially testable with string literals.
