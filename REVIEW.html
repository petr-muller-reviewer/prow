Verdict

Approve

Low-risk, additive CI config. No blocking issues. There's a real gap — hack/tools/go.mod isn't covered by the grouping, which will let the exact churn problem this PR is meant to solve recur for that module — but it doesn't make the change wrong or unsafe to merge, just incomplete. Worth raising as a comment / follow-up.

What this PR does

  • Adds .github/dependabot.yaml — the first dependabot config in this repo.
  • Enables weekly gomod version updates for the root module (directory: "/").
  • Defines four dependency groups — kubernetes, prometheus, aws, golang-x — via glob patterns, so dependabot bundles correlated bumps into one PR instead of one-per-package.
  • Goal per PR description: avoid the merge-conflict churn seen when e.g. AWS SDK submodules or golang.org/x/* packages release together and each gets its own PR.

Findings

should-fix

hack/tools/go.mod not covered by grouping

.github/dependabot.yaml:1-20

The repo has three Go modules: /, /hack/tools, /site. Only directory: "/" is configured here. hack/tools/go.mod vendors k8s.io/code-generator, sigs.k8s.io/*, and many github.com/aws/aws-sdk-go-v2/* indirect deps — exactly the families this PR groups. In fact, the two PRs merged immediately before this one (#806, #807) were separate golang.org/x/crypto bumps in / and /hack/tools landing at the same time — precisely the duplicate-PR/churn scenario this change is meant to prevent, and it will still happen for hack/tools since it's unconfigured.

version: 2
updates:
  - package-ecosystem: "gomod"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      kubernetes:
        patterns:
          - "*k8s.io*"
      ...
question

site/go.mod left unconfigured

.github/dependabot.yaml:1-20

site/go.mod currently has no overlap with the defined groups, so leaving it out is low-impact today — but it also means the site module gets no automated version updates at all (only security-alert-driven ones). Worth confirming this is intentional.

nit

No open-pull-requests-limit set

.github/dependabot.yaml:1-20

Defaults to 5 concurrent version-update PRs. Likely fine given grouping reduces volume, but since this is the repo's first gomod config, it's worth being a deliberate choice rather than an implicit default.

Things I checked and was fine with

  • Group glob patterns (*k8s.io*, *github.com/aws*, *github.com/prometheus*, *golang.org/x*) are valid dependabot syntax and correctly match the intended package families in the root go.mod (53 matching dependency lines).
  • Confirmed via git history that no .github/dependabot.yaml/.yml existed before this PR — this is a clean, config-only addition with nothing to regress.
  • Change has no code/security surface; worst case of an imperfect group definition is suboptimal PR batching, not a functional or security issue.

  • Any plan to add site/go.mod for version updates, or is that module intentionally left to security-alert-only updates?
