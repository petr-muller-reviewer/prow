What this PR does

  • Adds /override-sticky command that embeds a [prow:skip-retest] sentinel in the GitHub status description, telling Tide to treat the context as permanently passing for the current HEAD SHA even when the base branch moves.
  • Adds /override-cancel command to remove overrides (both regular and sticky) by setting their statuses to failure.
  • Regular /override now embeds baseSHA in the status description via ContextDescriptionWithBaseSha, fixing the ~48h Sinker-reaping expiry bug.
  • Tide's prowJobsFromContexts gains an IsSkipRetest check alongside the existing baseSHA match — sentinel and helper live in pkg/config.
  • No config schema changes, no new dependencies, no deployment ordering requirements.

Findings — Still Open

Should fix

should fix Regular /override should reuse baseSHA from the overridden context

pkg/plugins/override/override.go:513

baseSHA, err := baseSHAGetter()

baseSHAGetter() fetches the current base branch HEAD at override time. For regular /override, this is semantically wrong — the override just changes the verdict from fail to success, it shouldn't claim the job ran against a different base. Should reuse the baseSHA already embedded in the overridden context's description (via BaseSHAFromContextDescription). Fall back to the current base SHA only if the original context has none.
