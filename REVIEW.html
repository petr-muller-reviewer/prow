What this PR does

  • Adds a validMetricLabel() helper that strips invalid UTF-8 sequences using strings.ToValidUTF8(value, "").
  • Wraps the path and user_agent metric label values through this helper before passing them to prometheus.Labels{}.
  • Prevents a panic in prometheus.(*HistogramVec).With() triggered by a JNDI/Log4Shell-style probe containing \xbf (invalid UTF-8) in the User-Agent header.
  • Reformats the label map construction from a single line to one key per line (readability improvement).

Findings

Should fix

[Should fix] No test for invalid UTF-8 handling 2/3 reviewers

pkg/metrics/http_test.go

The existing TestHandleWithMetricsCustomTimer sets up the full tracing pipeline and could be extended with a second table entry using a User-Agent containing invalid UTF-8 bytes (e.g. "bot\xbf"). This would verify the fix prevents the panic, serve as a regression test, and document the failure mode for future maintainers.

[Should fix] r.Method not sanitized 2/3 reviewers

pkg/metrics/http.go:149

"method": r.Method,

r.Method is used as a Prometheus label value without validMetricLabel() wrapping. Go's HTTP server rejects non-token-character methods before they reach a handler (RFC 7230 section 3.1.1), so the practical risk is very low. However, wrapping it for consistency costs nothing and eliminates the question of which labels need sanitization and which don't — uniform application is easier to maintain than per-field reasoning.

Nits

[Nit] Redundant validMetricLabel on path

pkg/metrics/http.go:147

"path": validMetricLabel(simplifier.Simplify(r.URL.Path)),

simplifier.Simplify() returns either the constant string "unmatched" or concatenations of Represent() results from compile-time string literals — always valid UTF-8 regardless of input. The wrapping is harmless but could mislead a future maintainer into thinking Simplify can return arbitrary user input. Keeping it is fine if the team prefers uniform application; dropping it is also fine.

[Nit] Missing comment on validMetricLabel

pkg/metrics/http.go:158-160

func validMetricLabel(value string) string {
	return strings.ToValidUTF8(value, "")
}

The function name is clear, but a one-liner explaining why this exists (Prometheus panics on invalid UTF-8 label values) would help a future maintainer understand the severity of what happens without it.

Questions

[Question] User-Agent label cardinality as a DoS vector

pkg/metrics/http.go:84

The user_agent label stores the full raw User-Agent string. Every distinct UA creates a separate Prometheus time series. The crash payload in the PR description shows an attacker actively probing with crafted UAs. Even after this fix, an attacker sending many unique valid-UTF-8 UAs can cause unbounded metric storage growth. This is pre-existing and not introduced by this PR, but worth asking if there's a follow-up plan.

Things I checked and was fine with

  • method and status labels correctly left unwrapped in the original code — strconv.Itoa always produces ASCII, and r.Method is validated by Go's HTTP server (though wrapping it uniformly is suggested above).
  • strings.ToValidUTF8 with empty replacement is the right stdlib choice — strips invalid bytes without injecting replacement characters.
  • No changes to metric label keys or histogram bucket definitions.
  • Import of "strings" is correctly placed in the import block.
  • Fix is applied at the right layer: sanitization at the boundary where user input enters the metrics system.
  • Change is in the shared pkg/metrics/http.go used via TraceHandler, so all components using it benefit without individual changes.
  • Deployment risk is LOW: no config changes, no API changes, zero upgrade friction, safe to roll back.

Open questions for the author

  • Would you add a test case with an invalid UTF-8 User-Agent to TestHandleWithMetricsCustomTimer? The scaffolding is all there — just a second table entry.
  • Would you wrap r.Method in validMetricLabel() too? The practical risk is near-zero but it makes the sanitization uniform.
  • Any follow-up planned for the user_agent label cardinality? Varied valid-UTF-8 UAs can still cause metric storage growth.
