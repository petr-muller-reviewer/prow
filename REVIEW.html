Verdict: request changes

The fork-conflict path continues into normal repository and collaborator reconciliation, so a configuration error can mutate a repository found not to be the requested fork. Input validation also accepts a multi-segment upstream path. Both should be resolved before merge.

What this PR does

  • Adds declarative fork: configuration and creates organization forks through GitHub's forks API.
  • Waits for created forks, then reconciles their configured metadata and collaborators.
  • Adds --fix-forks, inheriting from --fix-repos unless explicitly set.
  • Emits a fork's parent in --dump output.

Findings

Blocking

Do not reconcile a repository after its fork validation fails

cmd/peribolos/main.go:1006-1027

configureForks reports a same-name non-fork or wrong-upstream fork through forkErr, but configureOrg still runs repository and collaborator reconciliation with no successful mapping for that entry. Those paths can mutate the conflicting repository's metadata or collaborators. Exclude failed fork entries from downstream reconciliation, or stop before mutating them.

if forkErr != nil {

Should fix

Reject fork.from values with extra path segments

cmd/peribolos/main.go:1363-1366

strings.SplitN(..., "/", 2) accepts owner/repo/extra, then uses repo/extra as a GitHub API path segment. Require exactly two nonempty segments so invalid input fails validation.

parts := strings.SplitN(repoCfg.Fork.From, "/", 2)
if len(parts) != 2 || parts[0] == "" || parts[1] == "" {
    validationErrors = append(validationErrors, fmt.Errorf("invalid fork from format %q for repo %s, expected 'owner/repo'", repoCfg.Fork.From, repoName))
}
