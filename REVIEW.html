Bug Description

Sparse checkout with --depth 1 --filter=blob:none creates a shallow clone with only the sparse files. When it then tries to git merge the PR head commit, git sees unrelated histories because the shallow sparse clone doesn't have enough history to find a common ancestor.

Example failure: prow.ci.openshift.org/…

Execution Flow

How sparse checkout + PR merge works in clonerefs:

git init → git sparse-checkout init → git fetch --depth 1 --filter=blob:none … baseRef → git sparse-checkout set …
git checkout + branch --force → git fetch --filter=blob:none … PR SHA → git merge --no-ff — fails here
With --depth 1, the base fetch retrieves a single commit with no parents. When the PR commit is fetched, git cannot find a common ancestor → "unrelated histories" error. Removing --depth 1 fetches the full commit graph (but still no blobs), so merge works.

Key Points for Review

Performance Consideration

Without --depth 1, the initial fetch downloads the full commit graph (but no blobs, thanks to --filter=blob:none). For repos with very long histories, this is more data than before.

However, this is the correct tradeoff: a clone that can't merge is broken regardless of how fast it clones. Users who need to limit history can still set cloneDepth explicitly.
