Approve — Clean mechanical deduplication with no behavioral change. All class renames are consistently propagated across HTML, CSS, TypeScript, and tests.

What this PR does

  • Extracts a shared {{define "test-detail-rows"}} Go sub-template for the expandable test result rows that were duplicated four times: top-level failed, top-level flaky, group-level failed, group-level flaky.
  • Replaces four inline copies with {{template "test-detail-rows" .Failed}} / .Flaky / $group.Failed / $group.Flaky calls.
  • Unifies CSS class names from section-specific (failure-*, flaky-*, group-*) to a single detail-* namespace, collapsing redundant selectors in junit.css.
  • Updates the TypeScript event binding selector in lens.ts and the test expectation in lens_test.go to match the new class names.
  • Net reduction of ~158 lines of duplicated template markup.

Things I checked and was fine with

  • The unified template introduces an {{if eq $numTest 1}} branch to flaky code paths that previously always used the multi-run layout. Verified in lens.go:303-321 that flaky classification requires ≥ 2 test runs (mixed pass/fail status), so the single-run branch is dead code for .Flaky data. No behavioral change.
  • Grepped the entire repository for old CSS class names (failed-layout, flaky-layout, group-layout, failure-name, flaky-name, group-name, failure-text, flaky-text, group-text). No dangling references remain.
  • The lens_test.go expectation is updated from group-layout to detail-layout, consistent with the rename.
  • The TypeScript selector in lens.ts is correctly simplified from .failure-name,.group-name,.flaky-name to .detail-name.
  • Section-level identifiers (failed-tbody, flaky-tbody, group-tbody, group-header) are intentionally unchanged — they organize the page sections, not the detail rows.
