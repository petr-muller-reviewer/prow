Verdict: request changes. The --ignore-repos feature (the one issue #737 actually asked for) is correct, well-tested, and matches existing conventions. But --ignore-private-repos/--ignore-internal-repos — undisclosed additions not requested by the issue — have a confirmed bug: they only protect repos a team already has, not new grants declared in config. This was independently identified by every reviewer across both a single-pass review and a 3-specialist maintainer-review (code quality, maintainability, deployment risk) plus advisor synthesis. Fix or explicitly document the gap, and disclose the scope expansion, before merge.

What this PR does

  • Adds --ignore-repos (comma-separated, repeatable, case-insensitive) so named repos are skipped entirely during team-repo reconciliation — never added, updated, or removed. This is the feature #737 requested and it works correctly.
  • Propagates the ignore set recursively into child-team reconciliation.
  • Also adds --ignore-private-repos and --ignore-internal-repos (undisclosed in the PR description/issue), backed by a new Visibility field on github.Repo.
  • Adds unit tests for flag parsing, the ignoredRepos helper, and configureTeamRepos behavior — but no test covers the private/internal "new grant" gap below.

Findings

Blocking

Blocking--ignore-private-repos/--ignore-internal-repos don't prevent new grants

cmd/peribolos/main.go:1498-1523

Independently confirmed by all 3 maintainer-review specialists (code quality, maintainability, deployment risk).

privateRepos/internalRepos are populated only from repos ListTeamReposBySlug currently returns for the team (the "have" side). A private/internal repo present in team.Repos (want) that the team does not yet have is never added to those sets — so peribolos will still add it despite the flag. Example: org.yaml declares team-x should get Write on private repo secret-repo, which team-x doesn't have yet — --ignore-private-repos will not stop that grant. This contradicts the PR's "skip ignored repos on both sides of the diff" framing for these two flags. No test exercises this case.

for wantRepo, wantPermission := range want {
    repoName := strings.ToLower(wantRepo)
    if ignoreRepos.Has(repoName) || privateRepos.Has(repoName) || internalRepos.Has(repoName) {
        continue
    }

cmd/peribolos/main.go:1510

repo.Visibility == "internal" is a bare string comparison with no constant/enum in pkg/github, unlike other GitHub API enums in the package. A typo or API change would silently break the feature.

Should fixNo logging when repos are skipped by ignore flags

cmd/peribolos/main.go:1503-1516

Ignored/private/internal repos are silently excluded with no logrus line, unlike other reconciliation actions in this file. Reduces operator visibility when auditing dry-run (--confirm=false) output.

Nits

NitignoredRepos manual comma-splitting undocumented

cmd/peribolos/main.go:163-174

flagutil.Strings.Set does not split on commas itself — it appends the raw argument once per --flag=value occurrence. ignoredRepos correctly splits/trims/lowercases itself, but a short comment explaining why (vs. the existing, non-splitting Strings.StringSet()) would help future readers.

NitconfigureTeamRepos growing to 8 parameters

cmd/peribolos/main.go:1490

3 new ignore-related params threaded through unchanged on every recursive child-team call. Consider bundling them into a small struct if more ignore knobs are added later.

NitNew Visibility field lacks a doc comment

pkg/github/types.go:335

Visibility string has three-way semantics (public/private/internal) but no comment. Also worth noting it may be empty on older GitHub Enterprise Server versions predating this API field — in which case --ignore-internal-repos fails safe but silently.

Nitcmp.Diff argument order reversed in new test

cmd/peribolos/main_test.go:196

cmp.Diff(actual, expected) reverses the conventional cmp.Diff(want, got) order; harmless here but inconsistent.

Things I checked and was fine with

  • go build ./cmd/peribolos/... ./pkg/github/... succeeds.
  • go test ./cmd/peribolos/... passes, including new tests for ignoredRepos, ignore-repos/private/internal behavior in configureTeamRepos, and child-team propagation.
  • --ignore-repos matching is case-insensitive consistently in both the have-building and want-diffing loops.
  • Flag naming follows the existing --ignore-* convention (--ignore-secret-teams, --ignore-enterprise-teams).
  • No markdown docs reference these flags, so none needed updating.
  • New Visibility field is additive-only on github.Repo; grepped other consumers (pluginhelp/hook, plugins/blunderbuss, plugins/lgtm, plugins/project, github/fakegithub, branchprotector, checkconfig) — none reference .Visibility, no deserialization risk for existing payloads.
  • All new flags default to no-op values (empty flagutil.Strings, false booleans) — no behavior change for operators who don't pass them; safe rollback, no config migration needed.
