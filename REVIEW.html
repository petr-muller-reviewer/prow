Title: Migrate to Pub/Sub v2
Head SHA: 578f7668f880883394c56d9da777c27b119dd79a
Base: main
Reviewed at: 2026-08-18T21:04:05Z
Verdict: Approve

Clean, well-tested migration off the deprecated Pub/Sub v1 client. The one behavior change worth scrutiny (dropping Synchronous mode) was verified against the v2 library's flow-control source and does not regress fairness. Only two low-severity nits found, neither blocking.

What this PR does

  • Migrates pkg/pubsub and its callers from cloud.google.com/go/pubsub v1 to cloud.google.com/go/pubsub/v2.
  • Replaces the removed ReceiveSettings.Synchronous = true with NumGoroutines = 1 on the subscriber, relying on v2's default client-wide flow controller for cross-replica fairness.
  • Adds shared test fixture helpers in pkg/testutil/fixtures.go (WriteCredentialsFile, WriteAuthorizedUserCredentialsFile) and adopts them in some tests.
  • Build and full test suite pass on the PR head.

Findings

Nit

Comment misattributes fairness guarantee to NumGoroutines

pkg/pubsub/subscriber/server.go:98
// Use one pull stream so multiple subscriber replicas can share work fairly.
NumGoroutines: 1,

The comment attributes fairness to the stream count, but in pubsub/v2 fairness actually comes from the default (non-per-stream) client-wide flow controller keyed on MaxOutstandingMessages, which applies regardless of NumGoroutines. Pinning NumGoroutines = 1 mainly guards against the library's documented future default flip of EnablePerStreamFlowControl to true (which would multiply the outstanding-message cap by NumGoroutines). A future contributor trusting this comment could raise NumGoroutines for throughput and reintroduce that problem once the default flips.

Nit

Duplicated credentials-fixture logic instead of reusing new test helper

pkg/io/opener_test.go:134
f, err := os.CreateTemp(t.TempDir(), "creds-*.json")
...
f.Write(...)
f.Close()

This PR adds pkg/testutil/fixtures.go and uses it earlier in this same file, but Test_opener_SignedURL a few lines below still hand-rolls an equivalent credentials fixture. The same duplicate pattern also remains in pkg/spyglass/storageartifact_fetcher_test.go (~line 443), a file this PR already edits nearby. Three independent copies of the same fixture logic can now drift out of sync.

Things I checked and was fine with

  • Build and full test suite pass on the PR head.
  • The pre-existing panic in pkg/pubsub/subscriber/subscriber_test.go also reproduces on the pre-PR commit — unrelated to this change.
  • Verified by reading vendored cloud.google.com/go/pubsub/v2@v2.6.0 source that replacing Synchronous=true with NumGoroutines=1 does not regress per-replica fairness: MaxOutstandingMessages is enforced by a client-wide flow controller shared across streams by default, independent of NumGoroutines.

Open questions for the author

  • Would you consider rewording the NumGoroutines = 1 comment to reference the future EnablePerStreamFlowControl default flip rather than implying the fairness guarantee comes from the stream count itself?
  • Any interest in a quick follow-up to converge Test_opener_SignedURL and storageartifact_fetcher_test.go onto the new testutil credential-fixture helpers, now that they exist?
