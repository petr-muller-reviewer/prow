Verdict: Approve with suggestions

Good, focused fix for a real data-loss bug. Adds a startup-time validation that detects duplicate cluster endpoints and fatals with an actionable error message. The code is correct, idiomatic, well-placed, and adequately tested. No blocking issues. One suggestion was independently flagged by all three review perspectives (code quality, maintainability, deployment risk): report all duplicate groups in a single error instead of returning on the first collision.

What this PR does

  • Adds validateUniqueClusters() that groups kubeconfig contexts by rest.Config.Host and rejects duplicates at startup.
  • Prevents a data-loss bug where duplicate-endpoint informers cause the reconcile loop at controller.go:462 to delete valid PipelineRuns that arrive through the "wrong" context.
  • Placed correctly after InClusterContext removal and allContexts truncation, so it validates exactly the config set that will create informers.
  • Only affects the pipeline (Tekton) controller running with --all-contexts; single-context mode is unaffected.
  • Includes table-driven tests covering unique, duplicate, empty, and single-config cases.

Findings

Should fix

[should-fix] Only the first duplicate collision is reported flagged by all 3 reviewers

cmd/pipeline/main.go:114-119

for host, ctxs := range hostToCtxs {
    if len(ctxs) > 1 {
        sort.Strings(ctxs)
        return fmt.Errorf("contexts %v resolve to the same cluster endpoint %s; deduplicate them in the kubeconfig", ctxs, host)
    }
}

The function returns on the first collision found. If an operator has multiple independent duplicate groups (e.g., contexts A/B both point at cluster X, and contexts C/D both point at cluster Y), they must restart repeatedly to discover each one. Collecting all violations and returning a combined error gives operators the full picture in one cycle.

[should-fix] Non-deterministic error output from map iteration

cmd/pipeline/main.go:114

for host, ctxs := range hostToCtxs {

Even with the current early-return, which collision is reported first varies between runs due to map iteration order. If changed to collect all violations (per above), the groups also need sorting for stable, reproducible error output.

Nits

[nit] Test doesn't verify error message content

cmd/pipeline/main_test.go:120-128

err := validateUniqueClusters(tc.configs)
if (err != nil) != tc.wantErr {
    t.Errorf("validateUniqueClusters() error = %v, wantErr %v", err, tc.wantErr)
}

The duplicate-hosts test only checks wantErr: true. The operational value of this validation is the error message telling operators which contexts collide and at which endpoint. A strings.Contains check on the error for the colliding context names and endpoint would guard against regressions in message quality.

[nit] Missing test cases for 3-way collision and multiple duplicate groups

cmd/pipeline/main_test.go:86-128

A test with three contexts sharing the same host would exercise sort.Strings more meaningfully. A test with two distinct hosts each having duplicates would document the first-duplicate-wins behavior (or verify all-at-once reporting if changed per the should-fix above).

Questions

[question] String-based host comparison and URL normalization

cmd/pipeline/main.go:112

hostToCtxs[cfg.Host] = append(hostToCtxs[cfg.Host], ctx)

rest.Config.Host values like https://k8s.example.com and https://k8s.example.com:443 point at the same server but won't match with string comparison. Similarly, trailing slashes could differ. In practice, client-go's kubeconfig loader produces consistent Host values, so this is likely fine. Worth acknowledging as a known limitation rather than complicating the code.

Things I checked and was fine with

  • Placement in main() — validation runs after delete(configs, kube.InClusterContext) and the allContexts truncation, so it checks exactly the config set that creates informers.
  • No impact on single-context mode — when --all-contexts is false, configs is truncated to a single entry before validation runs; the check is a no-op pass-through.
  • The underlying bug analysis is correct — confirmed at controller.go:462 that a context mismatch falls through without setting wantPipelineRun = true, leading to deletion.
  • Pure function shape — map[string]rest.Config in, error out, no side effects, trivially testable.
  • Deterministic context names in error — sort.Strings(ctxs) stabilizes the within-group ordering despite non-deterministic map iteration.
  • Test structure — table-driven, consistent with existing TestOptions, covers boundary cases (empty, single, unique, duplicate).
  • Import additions — sort (stdlib) and k8s.io/client-go/rest (already a transitive dep) are appropriate and minimal.
  • Clean failure semantics — check runs before any informers/clients are created; no partial initialization or resource leaks on failure.
  • Rollback safety — reverting removes the check; controller starts again (data-loss bug returns, but no new breakage).

Open questions for the author

  • Have you considered collecting all collisions and reporting them in a single error, so operators don't need multiple restart cycles to find every misconfiguration?
  • Is URL normalization (default ports, trailing slashes) a practical concern in the environments where this controller runs, or are kubeconfig generators consistent enough that string comparison is reliable?

Followups

Report all duplicate collision groups in a single error

Category: deferred-review  |  Necessity: should  |  Where: cmd/pipeline/main.go:114-119

validateUniqueClusters returns on the first collision group found. An operator with multiple independent sets of duplicate endpoints must fix one, restart, discover the next, and repeat. All three reviewers flagged this during review and agreed it was non-blocking but worth fixing as followup.

In kubernetes-sigs/prow, following PR #749 ("fix(pipeline): reject duplicate cluster endpoints at startup",
head commit 93096b1e06a8d9ddaf7ddc3b6c95f482a4d3c4fb), the function validateUniqueClusters in
cmd/pipeline/main.go currently returns on the first collision group it finds. An operator with multiple
independent sets of duplicate endpoints (e.g. contexts A/B both pointing at cluster X, and contexts C/D
both pointing at cluster Y) must fix one, restart, discover the second, fix that, and restart again.

Task: Modify validateUniqueClusters (cmd/pipeline/main.go:109-121) to collect all duplicate groups before
returning, then emit a single combined error listing every collision. Requirements:

1. Collect all host entries where len(ctxs) > 1 into a slice of formatted strings.
2. Sort the context names within each group (sort.Strings(ctxs) -- already done for the single-group case).
3. Sort the resulting slice of group error strings so the combined error is deterministic across runs.
4. Join them into one error message that preserves the existing guidance ("deduplicate them in the kubeconfig").
5. Add a test case with two distinct hosts each having duplicate contexts (e.g. ctx-a and ctx-b both pointing
   at https://a.example.com, and ctx-c and ctx-d both pointing at https://b.example.com) that asserts:
   - err is non-nil
   - the error message contains both host endpoints
   - the error message contains all four colliding context names

Acceptance criteria:
- All existing tests in cmd/pipeline/main_test.go still pass.
- The new test case passes.
- The function still returns nil when all hosts are unique.
- go build ./cmd/pipeline/... succeeds.

Out of scope: Do not change the host-comparison logic (raw string comparison of cfg.Host is intentional).
Do not add URL normalization. Do not touch controller.go or any other file.
