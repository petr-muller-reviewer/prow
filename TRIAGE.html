Verdict

Accepted bug. A former Prow bot account is being classified as a human after the instance moved from PAT authentication to a GitHub App, activating an unconditional manual-label approval bypass.

What the issue reports

  • A sig-network KEP was initially approved under the sig-network OWNERS rules.
  • The PR was changed to a sig-architecture KEP, where the author is not an approver.
  • The approved label remained and the notifier reported a manually added approval bypass.
  • The reported approval was therefore no longer valid for the current changed files.

Analysis

Reproducibility / observed behavior

The affected PR's sole approved label-add event was performed by k8s-ci-robot on 2026-02-16. The maintainer confirmed that Prow previously used a different PAT account and now uses a GitHub App; the historic label was consequently seen as manual. The label was manually removed as an immediate mitigation.

Probable cause

WasLabelAddedByHuman checks the actor on the last label-add event against only the current authenticated bot identity. A different former bot identity therefore returns “human.” The approve plugin feeds that result into ManuallyApproved, and IsApproved makes it an unconditional alternative to current OWNERS requirements.
