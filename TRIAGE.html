Verdict

Accepted — legitimate feature gap, already largely fixed by a stalled PR. Deck has no concept of a configurable base path in its routing, templates, or frontend JS, so it cannot be served correctly behind a reverse-proxy subpath. The gap is real and well-described. A near-complete fix already exists as PR #576, but that PR has been stalled for roughly 3.5 months with failing CI and unresolved review feedback — the issue's disposition is tied entirely to that PR's fate, not to fresh triage work on #376 itself.

What the issue reports

  • Deck deployed behind an nginx ingress rewriting /prow/?(.*) to the Deck service is reachable at https://infra.example.com/prow, but static assets and the prowjobs.js data API are requested against the domain root instead of the subpath.
  • Reporter (loispostula) read the code and found no configuration option to set a URL prefix for Deck.
  • Confirmed as a valid bug/feature gap by the maintainer (/kind bug applied same day).
  • A contributor (tsj-30) picked it up in September 2025 and has an active, substantial pull request open since December 2025.

Analysis

Reproducibility / observed behavior

No live repro needed — confirmed directly from the code. A repo-wide search for BasePath/base-path/subpath/prefix under cmd/deck/ and pkg/deck/ at the triage SHA turns up no configuration or flag related to a URL prefix — only unrelated GCS-prefix variables and TypeScript Prefix fields. Any subpath deployment will 404 on static assets and mis-navigate exactly as reported.

Probable cause

Deck's routing is entirely root-relative, and URL construction is inconsistent between layers:

  • cmd/deck/main.go registers every route on a single http.NewServeMux() using literal root-relative paths (e.g. /static/, /prowjobs.js, /tide, Spyglass routes) — nothing derives from configuration.
  • cmd/deck/template/base.html emits absolute asset and nav URLs (/static/style.css, /pr, /tide), while the inline data-fetch <script src> tags in index.html, pr.html, tide.html, command-help.html, and plugins.html happen to use relative paths (no leading slash). Under a subpath, the absolute paths break; only the accidentally-relative ones keep working.
  • No central frontend URL-builder exists: static/pr/pr.ts, static/common/rerun.ts, static/common/abort.ts, static/spyglass/spyglass.ts, and static/prow/prow.ts each construct URLs independently, several via window.location.origin plus a hardcoded absolute path.
