Verdict

Accepted — moderate Tide bug.
This is a focused, reproducible regression in user feedback after #930 intentionally changed a changed-files failure from a subpool-wide error to per-PR exclusion. The fix should preserve an exclusion reason through both Tide controllers and, if dashboard visibility is required, represent an empty diagnostic-only subpool.

What the issue reports

  • GitHub can return 422 when a large PR's changed-file diff cannot be generated.
  • For a file-dependent presubmit, Tide now excludes only that PR, allowing its peers to merge.
  • The excluded PR gets no actionable Tide explanation and is rediscovered on every sync.
  • It may misleadingly show In merge pool. or a generic retesting status.
  • The Tide dashboard also lacks the exclusion reason.

Analysis

Reproducibility / observed behavior

A PR whose required-presubmit selection needs changed files reproduces the issue when GitHub's pull-files endpoint returns 422. It is excluded on every Tide sync. The #930 behavior intentionally lets a peer PR in the same subpool continue, but no status tells the excluded PR author why it cannot proceed. The external limitation is documented in #914.

Probable cause

presubmitsByPull logs the changed-files error, deletes any partial presubmit collection, and omits the PR from sp.prs, but does not retain a structured diagnostic:

if changedFilesErr != nil {
    log.WithError(changedFilesErr).Warn("Failed to determine required presubmits for PR, excluding from subpool")
    delete(presubmits, pr.Number)
    continue
}

statusUpdate transfers only blockers, pooled PRs, base SHAs, and required contexts. In expectedStatus, an excluded PR is therefore indistinguishable from an ordinarily non-pooled PR. If it fulfills a Tide query, it falls through to ProwJob lookup and can receive success or generic retesting output.
