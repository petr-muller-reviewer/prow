Verdict

Accepted. The checked-in verifier formats every Go file before computing its diff, so normal formatter execution always reaches the empty-diff success branch and mutates the working tree.

What the issue reports

  • make verify-gofmt passes malformed Go code after rewriting it.
  • make verify includes the same mutating check.
  • update-gofmt should retain write behavior; verification should only report failure.
  • Three tracked files are presently listed by a non-mutating formatter scan.

Analysis

Reproducibility / observed behavior

A non-mutating gofmt -s -l scan lists cmd/checkconfig/main.go, pkg/pjutil/filter_test.go, and pkg/plugins/rifle/rifle_test.go at the recorded main SHA.

Probable cause

hack/make-rules/verify/gofmt.sh:26-30 first formats all Go files in place. Its next command computes a diff only after that write, so the empty-diff branch exits zero unless gofmt itself errors.

Related code

hack/make-rules/update/gofmt.sh:26-27 is the appropriate owner of writes:

echo "Go version: $(go version)"
find . -name '*.go' -type f -print0 | xargs -0 gofmt -s -w

Makefile:91-96 intentionally exposes separate update and verify targets:

update-gofmt:
    hack/make-rules/update/gofmt.sh
verify-gofmt:
    hack/make-rules/verify/gofmt.sh

hack/make-rules/verify/all.sh:35-39 invokes the faulty script through make verify. No active or historical PR specifically addressing this defect was found.

  4. Demonstrate malformed temporary input fails without mutation; then run make verify-gofmt and git diff --exit-code on the clean tree.
