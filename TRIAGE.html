Verdict: accepted

This is an actionable Prow trigger-plugin bug. GitHub Actions workflow approval is broken both at initial /ok-to-test and after later pushes; the issue has a live API investigation and two focused open fixes.

What the issue reports

  • Fork PR workflows should be approved after a maintainer establishes ok-to-test trust.
  • New commits create new approval-gated workflow runs that still require manual action.
  • The feature must remain controlled by trigger_github_workflows.
  • The original implementation in #612 did not fully deliver the behavior.

Analysis

Reproducibility / observed behavior

@dklima measured that GitHub treats a multi-event event value as an exact string. event=pull_request OR pull_request_target returns no runs, including on cluster-api and kubeflow/notebooks. See the issue report.

Probable cause

  • GetPendingApprovalActionRuns() and GetFailedActionRunsByHeadBranch() use unsupported OR event filters, so neither path discovers relevant workflow runs.
  • Approval is called only from the /ok-to-test comment handler, not from later trusted push or human-applied label events.
  • Approval-gated runs are completed with conclusion action_required; they must not be rerun as failures.

Related code

pkg/github/client.go:2194-2302 builds the Actions queries and exposes the approval endpoint:

query.Add("event", "pull_request OR pull_request_target")
query.Add("status", "action_required")

pkg/plugins/trigger/generic-comment.go:147-154 contains the one-shot approval path:

if isOkToTest && trigger.TriggerGitHubWorkflows {
    approveGitHubActionsWorkflowRuns(c, org, repo, pr.Head.Ref, headSHA)
}

pkg/plugins/trigger/pull-request.go:123-151 handles synchronize and label events but does not call approval.

Related issues / PRs

  • #955: removes the invalid event query, paginates results, filters events client-side, and excludes action_required from retest candidates.
  • #956: depends on #955; approves after qualifying trusted PR events with bounded polling and revalidation.
  • #612: original comment-only implementation; incomplete.
  • kubernetes/test-infra#25210: pre-migration source issue.

What I checked

Recommended next steps

  1. Review and merge #955 before #956.
  2. Validate both on a fork PR with trigger_github_workflows: true, GitHub App actions: write, /ok-to-test, and a subsequent push.
  3. Decide whether #956's bounded in-handler polling and accumulated waiters need queueing or concurrency limits.
  4. After merge and live validation, close #194 as fixed and consider changing kind/feature to kind/bug.
