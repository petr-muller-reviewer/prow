Verdict

ACCEPTED — legitimate feature request, feasible, well-precedented, author committed to contributing a PR.

Deck and Hook are HTTP-only backends; there is no option to serve HTTPS directly. This forces all deployments to terminate TLS at the Ingress or load balancer, which is incompatible with organizational policies requiring HTTPS backends. The fix is mechanical: add optional --tls-cert-file and --tls-private-key-file flags to both components and branch on whether they are set, using the already-existing interrupts.ListenAndServeTLS(). Three reference implementations of this exact pattern exist in the same codebase. The lifecycle/rotten label is stale-bot automation — the issue was reopened by the author in October 2025 and they remain actively engaged.

What the issue reports

  • Deck and Hook currently accept only HTTP connections — TLS is terminated at the Ingress level.
  • The author's organization requires all Ingresses to use an HTTPS backend protocol (end-to-end encryption, not just edge TLS).

Analysis

Current behavior

Both Deck and Hook create an http.Server and pass it to interrupts.ListenAndServe():

cmd/deck/main.go:505-514 
server := &http.Server{Addr: ":8080", Handler: ...}
interrupts.ListenAndServe(server, 5*time.Second)
cmd/hook/main.go:263-277 
httpServer := &http.Server{Addr: o.port, Handler: ...}
interrupts.ListenAndServe(httpServer, o.gracePeriod)

Probable cause

Prow's original design assumed TLS termination at the network edge (standard Kubernetes ingress pattern). Deck and Hook were never given TLS flags. The interrupts package later gained ListenAndServeTLS for components like Admission, but Deck and Hook were not updated.
