Verdict

ACCEPTED

Legitimate, maintainer-authored follow-up cleanup for the /override plugin, filed by the same engineer (smg247) who authored PR #778, with precise, verified code references. Splits into two independent, moderate-effort (help-wanted) items: dropping now-redundant synthetic ProwJob creation, and reusing an already-embedded BaseSHA instead of always fetching the current one.

What the issue reports

  • Item 1: now that overrides embed BaseSHA: in the GitHub status description and Tide reads it via BaseSHAFromContextDescription, the synthetic passing ProwJob that /override creates may no longer be necessary — it previously existed only so Tide wouldn't force a retest, but gets reaped by Sinker after max_prowjob_age anyway.
  • Item 2: /override calls baseSHAGetter to fetch the current base branch SHA at command time, which may not match the BaseSHA the original overridden job actually ran against (already embedded in its status description). Proposes extracting the embedded value first, falling back to a fresh fetch only when none exists.
  • Both items reference specific review comment permalinks from PR #778's review thread.

Analysis

Why this is now possible

PR #778 ("sticky-override-for-head", merged as 0633879af) added prowJobsFromContexts to Tide, which reconstructs an in-memory (non-persisted) passing ProwJob for merge-eligibility purposes directly from a GitHub status description's embedded BaseSHA — no real cluster ProwJob required.
