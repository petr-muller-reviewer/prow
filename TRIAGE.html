Verdict

Accepted: fix clonerefs so a moved remote tag cannot fail an otherwise valid clone.

This is a legitimate Prow bug. Forcing only the existing all-tags fetch is the smallest compatible solution: it preserves tag availability and pruning while updating a stale local tag such as hcpctl-nightly. The deliberate trade-off is that jobs observe the remote's current tag, not a stale one.

What the issue reports

  • An upstream repository intentionally retargets hcpctl-nightly for new builds.
  • Prow invokes git fetch <repo> --tags --prune.
  • Git rejects overwriting the existing local tag with “would clobber existing tag”.
  • clonerefs records a failed clone and the job exits unsuccessfully.

Analysis

Reproducibility / observed behavior

A preexisting checkout holding a prior tag object and a remote that moves that tag is sufficient. Git normally protects local tags from this non-forced update. Prow retries this deterministic error for 64.5 seconds before recording failure.

Probable cause

pkg/pod-utils/clone/clone.go:257-284 creates an additive all-tags fetch before its targeted base-ref fetch:

skipTagFetch := refs.SkipFetchHead || sparseCheckoutSet
if !skipTagFetch {
    fetchArgs = append(fetchArgs, g.repositoryURI, "--tags", "--prune")
    commands = append(commands, g.gitFetch(fetchArgs...))
}
...
fetchArgs = append(fetchArgs, g.repositoryURI, fetchRef)

The all-tags invocation lacks --force or a forced tag refspec. The later targeted fetch resolves the checked-out ref. Sparse checkout already omits all-tag fetching and passes --no-tags, confirming the prefetch is tag availability rather than base-ref resolution.

Related code and tests

  • cmd/clonerefs/main.go:27-40 and pkg/clonerefs/run.go:40-158 orchestrate clone records and fail the job when configured to do so.
  • pkg/pod-utils/clone/clone.go:201-220,390-412 applies generic retry to every fetch.
  • pkg/pod-utils/clone/clone_test.go:62-864 asserts command construction, but no test retargets a real Git tag. test/integration/test/pod-utils_test.go:47+ tests normal decorated cloning only.
  • site/content/en/docs/components/pod-utilities/clonerefs.md:8-72 does not document tag-fetch semantics.

The command was touched by 6d00893891; sparse checkout later skipped it in 43e2154a6. No duplicate or fix PR was found. The maintainer's note that Git tags are generally immutable is correct, but Prow may explicitly choose to refresh the tags it requests.

Effort assessment

Level 1 (easy). The likely change is one argument in the clone command and its table-test expectations, plus an optional local/bare-repository regression test. It fits a new contributor familiar with Go tests and Git fetch behavior.
