What the issue reports

  • PRs with cncf-cla: no have occasionally been merged in the Kubernetes org — a legal/compliance concern that currently goes undetected until found manually.
  • Requests a Prow plugin that sends a Slack alert when a PR is merged without a valid CLA status.
  • The original suggestion was a generic alert; maintainer discussion narrowed it to a single-purpose, best-effort Slack notification checking the "EasyCLA" commit status context.
  • A Prometheus metrics approach was discussed and rejected by BenTheElder due to high cardinality (need to identify which PR/repo, not just count events).
  • petr-muller noted a complication with squash/rebase merge strategies where the original commit status is lost, but the PullRequestEvent payload still carries the pre-merge Head.SHA.

Analysis

Existing infrastructure

The slackevents plugin (pkg/plugins/slackevents/slackevents.go) already sends Slack alerts for two event types:

  • Push events — warns about manual merges, force pushes, branch operations by non-exempt users (notifyOnSlackIfManualMerge, line 137).
  • Generic comments — echoes SIG mentions to corresponding Slack channels (echoToSlack, line 192).

It does not register a PullRequestHandler, so it cannot react to PR merge events today.

CLA status checking

The CLA plugin (pkg/plugins/cla/cla.go:36) defines the authoritative status context:

claContextName = "EasyCLA"

It queries GetCombinedStatus(org, repo, pr.Head.SHA) to check CLA compliance and manages cncf-cla: yes / cncf-cla: no labels (pkg/labels/labels.go:29-30). BenTheElder explicitly stated the commit status is the source of truth, not labels.

PR merge detection pattern

The branchcleaner plugin (pkg/plugins/branchcleaner/branchcleaner.go:82-85) demonstrates the standard approach:

if pre.Action != github.PullRequestActionClosed || !pre.PullRequest.Merged {
    return nil
}

Proposed implementation

Register a PullRequestHandler (via RegisterPullRequestHandler at pkg/plugins/plugins.go:132-135). On PR merge:

  1. Filter: Action == PullRequestActionClosed && PullRequest.Merged
  2. Call GetCombinedStatus(org, repo, pr.Head.SHA)
  3. Look for "EasyCLA" context — alert if missing or not "success"
  4. Optionally check cncf-cla: no label as secondary signal
  5. Send Slack message to configured channels

Configuration would extend the Slack struct (pkg/plugins/config.go:597-600) with a new CLAWarning field, following the existing MergeWarning pattern (config.go:809-818).

Squash/rebase complication

For repos using merge strategy, merged commits inherit the status context from the PR head. For squash or rebase, the original commit status is lost on the new commit. However, the PullRequestEvent payload always includes Head.SHA (the pre-merge head commit), which retains the original status. A v1 can simply check this SHA and document the limitation.

  • PullRequestEvent payload includes Head.SHA regardless of merge strategy.
