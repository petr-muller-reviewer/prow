What the issue reports

  • When a job is overridden via /override, Tide re-triggers it every time the base branch HEAD moves (another PR merges).
  • Fine for "reviewed and accepted" overrides, but painful for "job is simply broken / irrelevant" overrides — maintainers must keep re-overriding the same job repeatedly.
  • Proposed a sticky_for_head config option, a [prow:sticky] status-description sentinel, and new /override-sticky / /override-cancel commands.
  • Linked prior discussion in #238 (2024), closed by the original reporter without a fix.
  • Since previous triage: reporter self-assigned (2026-06-29), opened PR #778 the same day, merged it 2026-07-14 — issue auto-closed.

Analysis

What actually shipped (PR #778) vs. what the issue proposed

The design evolved materially across the PR's 7 commits before merge:

  1. No config gate in the final version. The issue proposed (and an early PR commit implemented) a per-repo plugins.Override.StickyForHEAD boolean gating the new commands. A later commit removed the gate entirely — /override-sticky and /override-cancel are unconditionally available wherever the override plugin runs. Confirmed by fetching the merged blob: no StickyForHEAD field remains in pkg/plugins/config.go.
  2. Dependency direction inverted mid-PR. An early commit made pkg/tide import pkg/plugins/override. A later commit reversed this: the sentinel (renamed [prow:skip-retest], from [prow:sticky]) and its checker IsSkipRetest() now live in pkg/config as a generic, override-agnostic contract. Tide no longer imports the override plugin at all.
  3. Fixed an adjacent latent bug as a side effect. Regular (non-sticky) /override now also embeds the baseSHA in its status description via ContextDescriptionWithBaseSha() — previously it didn't, so BaseSHAFromContextDescription() always returned "" for overrides and the synthetic ProwJob was orphaned once Sinker reaped the original (~48h). This is exactly the root cause an earlier triage pass had identified independently.
  4. Scope stays narrow: overrides clear on new push. The sentinel is embedded per-HEAD-SHA; a new commit produces a new SHA with no statuses, so jobs run normally again — matches the issue's stated scope and avoids any orphan-cleanup problem.
  5. /override-cancel [context] is new — removes sticky (or regular) overrides by flipping status back to failure, without requiring a push.

related-code config.SkipRetestSentinel / IsSkipRetest — generic skip-retest contract

  • pkg/config/config.go (added by PR #778) — deliberately owned by config, not override, mirroring the existing ContextDescriptionWithBaseSha/BaseSHAFromContextDescription pattern.
const SkipRetestSentinel = "[prow:skip-retest]"
func IsSkipRetest(description string) bool {
    return strings.Contains(description, SkipRetestSentinel)
}
