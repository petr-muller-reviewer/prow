Verdict

Accepted bug. Prow's opt-in GitHub Actions trigger sends an unsupported multi-event event query, so GitHub returns an empty successful result and /retest performs no rerun. PR #955 is the focused repair.

What the issue reports

  • With trigger_github_workflows: true, /retest does not rerun failed GitHub Actions workflows.
  • The reporter reproduced it on released versions and main.
  • Prow's OR-separated event value returns zero runs while a single pull_request event returns matching runs.
  • The empty API response produces no Prow error.

Analysis

Reproducibility / observed behavior

The issue's live API comparisons show a failed run without the filter and four pull_request runs with one event, but zero for Prow's multi-event string.

Probable cause

pkg/github/client.go:2194-2236 creates one event parameter containing three names joined by OR. GitHub treats it as an unknown exact event. pkg/github/client.go:2270-2304 repeats the pattern for pending approval runs.

Related code

pkg/plugins/trigger/generic-comment.go:169-196 reruns only discovered runs:
