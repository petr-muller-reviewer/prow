Accepted. Confirmed bug in the Tide status controller. Two gaps combine to suppress the correct "Not in merge pool" status when a required presubmit is newly added and existing PRs have never triggered it. Fix is a one-line nil-guard in contextCheckerGetterFactory, plus a new test case.

What the issue reports

  • When a presubmit changes from optional to always_run: true, open PRs with all other requirements met get silently stuck: the sync loop filters them out, but the status controller shows "In merge pool."
  • contextCheckerGetterFactory (status.go:787) overwrites config-derived RequiredContexts with nil for PRs not in the filtered pool, neutering MissingRequiredContexts.
  • requirementDiff (status.go:228-248) only checks contexts already posted to the commit; a never-triggered job is invisible.
  • Both gaps must fire together: the context is absent from the commit (Gap 1) AND the PR is filtered out (Gap 2).
  • Observed on openshift/operator-framework-operator-controller#737 after openshift/release#79764 made a presubmit required.

Analysis

Probable cause

Two gaps combine to produce the false status:

Gap 2 (primary) — contextCheckerGetterFactory overwrites RequiredContexts:

  • contextCheckerGetterFactory at pkg/tide/status.go:781-789 calls cfg.GetTideContextPolicy() which correctly computes required contexts from Prow config.
  • Line 787 then unconditionally overwrites: contextPolicy.RequiredContexts = requiredContexts
  • requiredContexts comes from requiredContextsMap(filteredPools) at pkg/tide/tide.go:814-826, which only has entries for PRs that survived filterSubpools.
  • For filtered-out PRs, requiredContexts[prKey(pr)] at pkg/tide/status.go:453 returns nil.
  • MissingRequiredContexts at pkg/config/tide.go:1025-1038 early-returns nil when RequiredContexts is empty.

Gap 1 (secondary) — requirementDiff only sees posted contexts:

  • requirementDiff at pkg/tide/status.go:228-248 calls unsuccessfulContexts which iterates commit.Commit.Status.Contexts.
  • A required job that never ran has no GitHub status, so it is invisible.
  • unsuccessfulContexts at pkg/tide/tide.go:878 does call MissingRequiredContexts, but Gap 2 zeroed the list.

Combined effect: requirementDiff returns diffCount == 0, hasFulfilledQuery = true at status.go:319. Falls through to the MissingRequiredContexts check at line 357 — still zeroed. Result: StatusSuccess with "In merge pool."

Reproducibility

Triggered by adding a required presubmit to a repo with open PRs that have all other requirements met. Observed in the OpenShift ecosystem: openshift/operator-framework-operator-controller#737 after openshift/release#79764 made openshift-e2e-aws-techpreview required. Sync loop logged the correct filter-out, but status controller simultaneously reported "In merge pool."

Test coverage

All existing requiredContexts test cases in TestExpectedStatus (status_test.go:525-710) set inPool: true. TestSetStatusRespectsRequiredContexts (status_test.go:2009-2066) also puts the PR in the pool. No test covers the bug scenario: PR not in pool with config-derived required contexts.
