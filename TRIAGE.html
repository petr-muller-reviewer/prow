kubernetes-sigs/prow#737

peribolos: add --ignore-repos flag for team-repo reconciliation
State open Labels (none at triage time) Triaged at 2026-05-30T13:33:41Z Main SHA 71428b9c282ee8c9e7e9512068fccce86e7915da Author marcusburghardt Opened 2026-05-29

Verdict

ACCEPTED

This is a legitimate, well-motivated feature request for peribolos. The gap is real: --fix-team-repos performs unconditional subtractive reconciliation with no per-repo escape hatch, making it unusable for organizations that manage some repo permissions outside peribolos. The proposed --ignore-repos flag mirrors the established --ignore-secret-teams / --ignore-enterprise-teams pattern exactly, requires changes to two files only, is fully backwards compatible, and has a contributor ready to implement it. Effort is moderate (Level 2 / help-wanted).

What the issue reports

  • --fix-team-repos removes any repo from a team's GitHub permissions if that repo is absent from the YAML config — there is no way to opt a repo out of this reconciliation.
  • Organizations managing some repo permissions outside peribolos (Terraform, manual, separate automation) cannot use --fix-team-repos without declaring every such repo in the config first.
  • The only current workaround is --ignore-secret-teams: make the controlling team secret so peribolos skips it. This is semantically wrong and reduces audit visibility.
  • The request is for a new --ignore-repos flag accepting a comma-separated repo list, following the --ignore-* naming convention already established in peribolos.
  • Author cites kubernetes/org#4365 as a real incident where missing team-repo config caused peribolos to strip publishing bot permissions; the --skip-removals emergency flag added then reverted would have been better served by targeted repo exclusion.

Analysis

Probable cause

CAUSE No per-repo escape hatch in configureTeamRepos

The removal loop at cmd/peribolos/main.go:1495-1500 iterates over the have map (repos currently on GitHub) and marks any repo absent from want (YAML config) for removal. There is no filtering step before this loop. The --ignore-secret-teams / --ignore-enterprise-teams pattern was never extended to repos, and configureTeamRepos accepts no options struct, so there is no natural injection point without a signature change.

// cmd/peribolos/main.go:1495-1500
for haveRepo := range have {
    if _, wantRepo := want[haveRepo]; !wantRepo {
        actions[haveRepo] = github.None  // unconditional removal — no opt-out
    }
}

Related code

CODE configureTeamRepos — primary function to modify

Reconciles team-repo permissions for one team and recursively for child teams. Implementation at cmd/peribolos/main.go:1468-1532. The fix is to delete ignored repos from have before the diff loop, and to extend the function signature to accept the ignore set.

CODE options struct & flag registration — convention to follow

cmd/peribolos/main.go:46-70 (struct) and cmd/peribolos/main.go:80-103 (registration). The new ignoreRepos flagutil.Strings field mirrors ignoreSecretTeams bool / ignoreEnterpriseTeams bool. requiredAdmins flagutil.Strings at line 54 is the type precedent for multi-value string flags.

CODE Call sites — both must be updated
  • Outer loop: cmd/peribolos/main.go:1011 — configureTeamRepos(client, githubTeams, name, orgName, team)
  • Recursive child call: cmd/peribolos/main.go:1526 — must propagate the ignore set or child teams bypass the filter entirely.
CODE TestConfigureTeamRepos — test infrastructure to extend

cmd/peribolos/main_test.go:2680-2888. Comprehensive table-driven tests using a fakeTeamRepoClient. No ignore-repo cases exist yet. Adding them is straightforward; the existing structure makes it easy to add: ignore-only repo, repo in both want and ignore, child-team propagation.

CODE configureTeams — model for passing ignore parameter

cmd/peribolos/main.go:713. Already models the pattern of passing ignoreSecretTeams and ignoreEnterpriseTeams as explicit parameters to a reconciliation function. Implementors should follow this exact approach for configureTeamRepos.

Related issues

ISSUE kubernetes/org#4365 — prior incident

Incomplete team-repo config caused peribolos to strip publishing bot permissions. An emergency --skip-removals flag was added (test-infra#30264) then reverted as too broad (test-infra#30392). Targeted repo exclusion would have been the right fix.

What I checked

  • configureTeamRepos does not accept an options struct — signature extension is required at all call sites.
  • flagutil.Strings / flagutil.NewStrings() is the correct type for a multi-value string flag; requiredAdmins at line 54 is the in-repo precedent.
  • No existing test in TestConfigureTeamRepos covers an ignore-repo scenario.
  • No YAML schema changes to pkg/config/org are needed for the CLI-flag approach.
  • configureTeams at line 713 already models passing an ignore parameter through a reconciliation function — a clean reference for the implementor.
  • Peribolos is entirely in cmd/peribolos/; no other packages affected by the proposed change.

Open questions

  • When a repo is in both the YAML want map and --ignore-repos, should peribolos skip it entirely (no add/update/remove) or only suppress removal? The issue's proposed have-only filter would still add the repo if absent from GitHub. The fully-invisible behavior (filter from both have and want) seems more defensible.
  • Should --ignore-repos also affect --dump output? (Likely no, but worth confirming with the contributor.)
