Verdict

Accepted — and already resolved on main.

This was a legitimate, repository-owned bug: the pipeline (Tekton) controller deleted valid PipelineRuns whenever two kubeconfig contexts resolved to the same underlying cluster. The original 2026-02-10 triage correctly identified the root cause and recommended a startup-validation fix; PR #749 implemented exactly that, merged 2026-06-16 and closed the issue. No further maintainer action is needed.

What the issue reports

  • Reporter runs multiple build clusters (cluster-a, cluster-b, cluster-c, plus default).
  • Mid-migration, they pointed a ProwJob's cluster: field at a named context that shared the same kubeconfig/API server as default.
  • The pipeline controller got confused between the two contexts pointing at the same physical cluster, and silently deleted running PipelineRuns.
  • Reporter pinpointed the offending code at cmd/pipeline/controller.go:463 themselves and asked whether validation was feasible.

Analysis

Reproducibility / observed behavior

Matches the fix author's own PR description almost verbatim: two contexts sharing a server endpoint each get their own informer; both see the same PipelineRun events; the "wrong context" one gets deleted.

Probable cause

The controller creates one informer per kubeconfig context, with no deduplication by underlying cluster identity. When two contexts share a server endpoint, both informers watch the same PipelineRun resources. The reconcile check ClusterToCtx(pj.Spec.Cluster) != ctx treats a context-name mismatch as "wrong cluster," even though the cluster is identical, and deletes the resource.

Related code

cmd/pipeline/controller.go:463 — the deletion trigger:

ClusterToCtx(pj.Spec.Cluster) != ctx  // true across duplicate contexts -> wantPipelineRun = false

cmd/pipeline/main.go:127-136 (pre-fix numbering) — pre-existing dedup precedent used as the template for the fix: InClusterContext → DefaultClusterAlias aliasing handled only the empty-string vs "default" case, not the general case of any two contexts sharing a server URL.
