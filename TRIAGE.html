Reusable presets for Tide merge criteria

kubernetes-sigs/prow#1082 · main_sha 9c8eff7c98cc · state open · labels kind/feature, area/tide · triaged_at 2026-11-20T00:46:29Z
verdict: accepted

Verdict

accepted — valid, in-scope Prow feature request; already implemented by open PR #1083.

The issue asks for named, reusable Tide query fragments so a centrally managed baseline of merge criteria does not have to be duplicated across sharded configs. It is written by a Prow maintainer, includes an example, and states the design constraints clearly; no duplicate exists. PR #1083 already implements the recommended design (authored/runtime type split, presets resolved after shard merge and before dedup, authored YAML preserved on save). Effort is Level 3 (Large) because the change adds a config surface on the shared load/validate path and changes the Go-visible TideGitHubConfig.Queries type.

What the issue reports

  • Tide config can be sharded per org and per repo, which lets repos tweak merge criteria but makes it hard to centrally enforce common elements such as merge-prohibiting labels and branch treatment.
  • Proposed feature: define named tide.query_presets (a reusable query fragment) and reference them by name from tide.queries; a query may use multiple presets.
  • List fields (labels, missingLabels, includedBranches, excludedBranches) would be unioned; scalar fields must not conflict, with checkconfig enforcing it.
  • Presets would be resolved during configuration loading, before the existing query deduplication; the authored configuration must survive a load/save round-trip without presets resolved.
  • The config surface needs preset awareness that runtime TideQuery does not, so the shared data structure should be split; the issue accepts an internal and external Go API break because Prow is not a library.

  • Test coverage on main: query validation and dedup are covered (pkg/config/tide_test.go, pkg/config/config_test.go, cmd/checkconfig/main_test.go); preset behavior is absent. PR #1083 adds pkg/config/tide_query_spec_test.go covering round-trip, slice isolation, composition, scalar-presence conflicts, invalid presets, cross-file references, and reload.

Open questions
