Verdict

Accepted — legitimate, well-specified feature request.

The cherrypicker external plugin currently discards original commit SHAs when creating cherry-pick PRs. The request to append (cherry picked from commit <SHA>) trailers is a standard git convention (git cherry-pick -x), well-motivated by downstream users (KubeVirt), and straightforward to implement via patch modification before git am. Effort level 2 (moderate). A contributor self-assigned three months ago but has not submitted a PR.

What the issue reports

  • Cherry-pick PRs created by the cherrypicker bot lack the original commit SHAs in their commit messages.
  • The author wants (cherry picked from commit <SHA>) appended to each commit message, matching git cherry-pick -x behavior.
  • Multi-commit PRs need each commit annotated with its own original SHA, not just the PR number.
  • Two approaches proposed: amend commits after apply, or modify the patch before apply.
  • Desired output demonstrated in kubevirt/kubevirt#15073 (manual cherry-picks); current output shown in kubevirt/kubevirt#15076 (bot-created).

Analysis

How the cherrypicker works today

The cherry-pick flow in server.go:handle():

  1. Fetches the entire PR as a single patch file via GitHub API (server.go:750-762, getPatch())
  2. Checks out the target branch, creates a new branch (server.go:562-607)
  3. Applies all commits at once with r.Am(localPath) (server.go:616) — runs git am --3way
  4. Pushes immediately (server.go:635)
  5. Creates a PR with cherry-pick metadata in the body (server.go:654)

There is no step between Am() and Push() where commit messages could be modified. This gap (lines 616–635) is the insertion point.

Probable cause

The feature simply was never implemented. The cherrypicker uses git am (not git cherry-pick), which does not have a -x equivalent. The original commit SHAs are present in the patch file's From <SHA> headers but are consumed by git am internally and not propagated to commit messages.

  • cmd/external-plugins/cherrypicker/server.go:750-762 — getPatch() fetches PR patch from GitHub, writes to temp file.

  • pkg/git/v2/interactor.go:33-79 — Interactor interface has no commit-amend or rebase methods. Patch-modification approach avoids needing them.
  • cmd/external-plugins/cherrypicker/main.go:74 — --create-issue-on-conflict flag pattern to follow for a new CLI flag.

Recommended implementation approach

Modify the patch file before passing it to Am(). Parse each From <SHA> header, locate the corresponding commit message body in the patch, and append the (cherry picked from commit <SHA>) trailer. Write the modified patch, then Am() as usual. This keeps the change entirely within the cherrypicker plugin code — no interactor interface changes needed.
