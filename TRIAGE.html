Bottom line: Legitimate bug, root cause confirmed against current main, and a fix is already open in PR #849.
config.Agent.Set() (pkg/config/agent.go:403-425) advances its live config synchronously before attempting to deliver the corresponding Delta to subscribers over a channel with a 1-minute timeout; a timed-out delivery is dropped with no logging. status-reconciler is the only subscriber that trusts a delta's Before value as an authoritative diff baseline, so a dropped delta's config transition becomes permanently invisible to it — e.g. a newly added blocking presubmit may never get triggered on already-open PRs. PR #849 already implements the requested fix (self-tracked lastProcessed state diffed against the live Config(), plus a warning log on drop), with one review-worthy gap: it advances lastProcessed even when reconciliation errors.

What the issue reports

  • status-reconciler can permanently miss a Prow config change if it's still busy (e.g. listing PRs, calling GitHub) when the agent's 1-minute delta-delivery timeout elapses.
  • Because config.Agent's internal config has already advanced by the time delivery is attempted, the next delta's Before masks the dropped transition — there's no way to discover it was missed.
  • Concretely, a newly added blocking presubmit can go untriggered on already-open PRs indefinitely, until someone intervenes manually.
  • Proposes: track a private lastProcessed config in the reconciler, diff against the agent's live Config() rather than trusting delta.Before, advance lastProcessed only after successful reconciliation, and log a warning whenever a delta delivery times out.
  • Explicitly narrows the scope of #841, excluding the GitHub-ruleset context-retirement and Tide status-description concerns discussed there.

Analysis

Reproducibility / observed behavior

Requires status-reconciler to be busy for the full 1-minute delivery window when Agent.Set() fires (e.g. mid-GitHub-API-call), and a further config change to land afterward so the dropped transition is masked by the next delta's advanced Before. Verified by direct code reading — the mechanics as described match current main exactly, no discrepancies found.

Probable cause

Agent.Set() (pkg/config/agent.go:403-425) takes its lock, computes oldConfig from the current ca.c, builds delta := Delta{oldConfig, *c}, sets ca.c = c synchronously, then spawns one goroutine per subscriber:

go func(sub DeltaChan) {
    end := time.NewTimer(time.Minute)
    select {
    case sub <- delta:
    case <-end.C:
    }
    ...
}(subscription)

The timeout branch drops delta silently. Because ca.c already advanced before delivery was attempted, a dropped delta is unrecoverable through the agent alone.

statusreconciler.Controller.reconcile() (pkg/statusreconciler/controller.go:185-209) diffs delta.Before.PresubmitsStatic against delta.After.PresubmitsStatic directly, with no independently tracked "last processed" state on Controller — so a dropped delta's transition is never re-diffed by any later delta.
