Verdict

DUPLICATE

The issue bundles two claims judged out of scope or working-as-intended (a GitHub-ruleset-orphaned required context, and Tide's status-message gate ordering), plus one real bug — config.Agent.Set silently dropping a config delta on subscriber timeout — surfaced by a maintainer during discussion. That real bug was correctly split into a dedicated issue, #848, and #841 was closed as its duplicate on 2026-08-13. No further action is needed on #841 itself.

What the issue reports

  • A required GitHub context added but never triggered, then removed from config, can never be retired by status-reconciler because its retire condition requires the context to have already posted at least once.
  • Real-world trigger cited: openshift/oadp-operator#2346, a PR permanently BLOCKED by two never-triggered required contexts under Tide's github_merge_blocks_policy: block.
  • Secondary claim: Tide's status message hides the "blocked by GitHub" reason behind other, earlier-checked requirement gates.
  • Proposes code changes to migrator.RetireMode and requirementDiff, plus a new Prometheus gauge for pool-exclusion reasons.
  • Discussion (Prucek) redirected the issue toward a different, verified root cause: status-reconciler can silently miss config changes entirely when config-delta delivery times out.

Analysis

Probable cause — as originally reported

The reporter's own cited incident (#2346) turns out to be blocked by a GitHub ruleset, not a Prow-managed branch-protection required check. branchprotector (pkg/config/branch_protection.go) only speaks the legacy Branch Protection API and never reconciles rulesets, so this class of orphaning is out of scope for any Prow component — confirmed by petr-muller in the thread.

Related code — retire condition (accurate but not the operative cause)

pkg/statusreconciler/migrator/migrator.go:171-174:

case stateAny:
    if !found {
        return nil
    }

Requires the context to already be present in the PR's combined status for a stateAny retire condition to match — a context that never posted has no entry, so retirement never fires. Technically correct as described, but not what caused #2346 (see above).

Related code — Tide status-message gating (working as intended)

pkg/tide/status.go:265-267 gates the github_merge_blocks_policy: block description behind desc == "", last of ~7 requirement gates. Judged intentional: status length is limited, and earlier reasons (missing label, failing test) are usually more actionable for the PR author than a GitHub-side ruleset block they can't self-resolve.

Cause — the real bug

pkg/config/agent.go:403-421 (Agent.Set):

for _, subscription := range ca.subscriptions {
    go func(sub DeltaChan) { // wait a minute to send each event
        end := time.NewTimer(time.Minute)
        select {
        case sub <- delta:
        case <-end.C:
        }
        ...
    }(subscription)
}

If a subscriber's channel send doesn't complete within one minute, the delta is silently dropped — but ca.c has already advanced synchronously. status-reconciler trusts the delta's Before field as its diff baseline rather than tracking its own last-processed config, so a dropped delta's changes (e.g. a newly added blocking presubmit) are never diffed against, and triggerNewPresubmits (controller.go:186/:211-268) never runs for them. Identified by Prucek (MEMBER) in this comment; verified independently by reading the code.
