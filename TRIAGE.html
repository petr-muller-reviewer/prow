Legitimate build-infra request. The immediate symptom (stale base images) has already been patched twice by hand (PR #567, PR #747), but the automation the issue actually asks for isn't in place yet. PR #796 supplies half of it — a generic-autobumper config — but is unreviewed, and the other half (a periodic job in kubernetes/test-infra to invoke it) doesn't exist. Keep open; the path to closing it is concrete and small.

What the issue reports

  • Prow's base images (pinned in .ko.yaml) hadn't been updated since July 2025, so images built for Prow components carried an outdated gcr.io-registry base.
  • Reporter asked whether these could be refreshed and, implicitly, kept refreshed going forward.
  • Follow-up discussion (petr-muller, upodroid, BenTheElder) converged on a plan: get dependabot bumping enabled upstream in kubernetes/test-infra first, then add a generic-autobumper config in this repo to auto-bump .ko.yaml.
  • BenTheElder separately floated a longer-term idea: move Prow-only base images into this repo so their lifecycle isn't tied to test-infra's larger, unrelated CI image set.
  • The bot marked the issue lifecycle/rotten after 90+30 days of inactivity — but there has been real activity (two manual bumps, one open fix PR) the bot doesn't see as issue comments.

Analysis

Reproducibility / observed behavior

The staleness described in the issue has already recurred once since filing, confirming it's a systemic gap rather than a one-off:

da4351c35 Update base container images to v20251206-8481528a19   (2025-12-15)
6312f82b3 Update base container images to v20260512-1f34ef0df3   (2026-06-09)

Both are human-authored PRs (prad9192, valen-mascarenhas14) — not bot commits — meaning nothing currently keeps .ko.yaml current on its own.

Probable cause

hack/autobump.yaml (added by PR #796) configures generic-autobumper correctly, but a config file alone does nothing — it needs a periodic ProwJob to invoke generic-autobumper --config=hack/autobump.yaml on a schedule. Job definitions for this repo live in a different repository, kubernetes/test-infra, under config/jobs/kubernetes-sigs/prow/. A search of that path today turns up prow-periodics.yaml, prow-presubmits.yaml, and prow-postsubmits.yaml — none of which reference generic-autobumper or hack/autobump.yaml. So the automation is half-built.
