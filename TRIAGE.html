[Feature] Trigger required tests with /test-required

Verdict

ACCEPTED — legitimate feature request, ready for a contributor with one design clarification needed.

The gap is real and non-redundant: neither /test all nor /retest-required can trigger required presubmits that have AlwaysRun: false and no file-change pattern (NeedsExplicitTrigger() = true). These are precisely the jobs the author wants to batch-trigger. The implementation is small (~50-80 LOC across 4 files) and follows established patterns with one non-obvious twist: the new filter must return forced = true for explicit-trigger required jobs, or the author's use case won't actually be solved.

What the issue reports

  • The metal3-io project has required presubmits that are not auto-triggered (AlwaysRun: false, no run_if_changed) — they must be manually kicked off to save resources.
  • Today, contributors must copy each pending job name from the GitHub checks UI and type /test <name1> <name2> ... — tedious across many dependabot PRs and many repos.
  • The request is for a single /test-required command that triggers all required presubmits not yet run, analogous to how /retest-required handles required jobs that failed.
  • /test all is not a substitute: it also runs optional jobs (wasteful) and skips explicit-trigger required jobs entirely.

Analysis

Why existing commands don't help

  • /test all — TestAllFilter.ShouldRun returns !p.NeedsExplicitTrigger(), false, false. For required jobs where NeedsExplicitTrigger() = true, this is false — job skipped. Also runs optional jobs.
  • /retest-required — RetestFilter.ShouldRun returns failed || (!p.NeedsExplicitTrigger() && !allContexts.Has(p.Context)). The "not yet run" clause also gates on !NeedsExplicitTrigger() — explicit-trigger required jobs still skipped unless they've failed.

Probable cause of the gap

All bulk-trigger commands were designed around auto-triggered jobs. Explicit-trigger jobs (manually kicked off) were always expected to be named explicitly in the comment. No command was ever built to say "force-start all required explicit-trigger jobs that haven't run yet."

Key implementation insight

The @Prucek implementation sketch in the comments would not solve the author's use case if naively followed. The sketch says "new filter following the RetestRequiredFilter pattern." But RetestFilter.ShouldRun uses !p.NeedsExplicitTrigger() in the "not yet run" clause — which skips the exact jobs the author wants to trigger.

The correct TestRequiredFilter.ShouldRun should be approximately: 
func (trf *TestRequiredFilter) ShouldRun(ps config.Presubmit) (bool, bool, bool) {
    if ps.Optional { return false, false, false }
    notRun := !trf.allContexts.Has(ps.Context)
    // forced=true for NeedsExplicitTrigger jobs so Presubmit.ShouldRun
    // bypasses the explicit-trigger check
    forced := notRun && ps.NeedsExplicitTrigger()
    return notRun, forced, false
}
