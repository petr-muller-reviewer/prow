Verdict

Accepted and completed.

This was a valid, actionable Prow trigger-plugin feature request. It is closed because PR #735 merged on 2026-08-19, not because it was invalid.

What the issue reports

  • Projects such as Metal3 use required presubmits that are intentionally not automatically triggered.
  • Users previously had to copy every pending job name into a separate /test <job> invocation.
  • /test all would run unnecessary jobs, while /retest addresses failures.
  • The requester preferred triggering the required manual jobs; the implementation names that capability /test-manual-required.

Analysis

Observed behavior and probable cause

Before the fix, /test all excluded jobs requiring explicit triggers and /retest-required only selected required failures. No bulk command selected required manual presubmits, making individual /test <job> commands necessary.

NeedsExplicitTrigger() identifies non-always_run jobs with no file-match conditions. PR #735 adds a dedicated filter that selects non-optional jobs in that class and returns forced=true, which makes Presubmit.ShouldRun bypass file-condition evaluation.

  • pkg/config/jobs.go:510-539 — defines NeedsExplicitTrigger() and honors forced presubmits.
  • pkg/pjutil/filter.go:141-155,261-307 — prior bulk filters and the new manual-required filter.
  • pkg/pjutil/filter.go:312-346 — command-to-filter wiring.
  • pkg/plugins/trigger/generic-comment.go:217-280 — command recognition and trigger dispatch.
  • pkg/plugins/trigger/trigger.go:147-153 — featured command help.

return true, true, false

The scope deliberately excludes optional and file-conditional jobs. It can rerun an already-present manual context, so it is not a status-aware missing-only command.
