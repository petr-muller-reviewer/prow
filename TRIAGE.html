Three competing PRs now exist: #849 (the original approach, held in maintainer review, effectively superseded), #870 (fixes the bug at the source for every subscriber, but is a breaking API change), and #871 (non-breaking, best-tested, but only patches this one subscriber and bundles an unrelated fix). What the issue reports

  • config.Agent.Set() advances its live config synchronously, then tries delivering the corresponding delta to subscribers over a channel with a 1-minute timeout; a timed-out delivery is dropped silently.
  • status-reconciler trusts a delta's Before value as ground truth, so a dropped delta's config transition becomes permanently invisible — e.g. a newly required blocking presubmit may never trigger on already-open PRs.
  • Proposed (in the issue) that status-reconciler track its own lastProcessed config and diff against the agent's live Config() instead of trusting delta.Before.
  • Since previous triage: three PRs (#849, #870, #871) now implement three different architectural answers to this; the maintainer (petr-muller) declined #849 in review and authored #870 and #871 as alternatives, without yet settling on which to land.

Analysis

Probable cause (unchanged since first triage)

Agent.Set() (pkg/config/agent.go:403-425) sets ca.c = c synchronously, then spawns a goroutine per subscriber attempting sub <- delta with a 1-minute timeout; the timeout branch drops the delta with no logging. Because ca.c already advanced, a dropped delta's transition is unrecoverable through the agent alone. statusreconciler.Controller.reconcile() (pkg/statusreconciler/controller.go:161-209) trusts delta.Before with no independent memory of what it actually processed, so the dropped transition is never re-diffed.

Related PRs — three competing fixes

related-prkubernetes-sigs/prow#849 — original fix, held in review

Consumer tracks lastProcessed, diffs against live Config() instead of delta.Before. 66-line diff, no tests. Held by maintainer review (petr-muller): "degrading the delta channel to be just a notification mechanism for the destination to do its own config fetch feels like it breaks a fairly nice abstraction and separation of concern." Effectively superseded by #870/#871. State: do-not-merge/hold, no lgtm.

related-prkubernetes-sigs/prow#870 — fix at the source, breaking change

Makes config.Agent.Subscribe()/Set() lossless via single-slot coalescing at the source — Subscribe() changes from a caller-supplied channel to an agent-owned, receive-only, coalescing channel; removes the goroutine/timeout mechanism entirely; fixes the bug for every subscriber, not just status-reconciler. 236-line diff, 2 new tests in pkg/config/agent_test.go. Breaking API change for external vendorers of Subscribe — Prucek: "this is a breaking API change for anyone vendoring pkg/config and calling Subscribe directly... I checked ci-tools and it doesn't call Subscribe... but I haven't checked other consumers... /hold" (gave lgtm+hold together). Currently failing pull-prow-verify-lint and pull-prow-unit-test-race-detector-nonblocking; also flagged do-not-merge/invalid-commit-message.

related-prkubernetes-sigs/prow#871 — decouple + retry, non-breaking

Dedicated goroutine drains the delta channel immediately on the consumer side (agent's sender never blocks/drops); lastReconciled advances only after a successful reconcile(). Adds bounded retry (5 attempts, 30s delay, not CLI-configurable) so a "poison" config can't wedge the controller forever. 394-line diff, includes a realistic drop-simulation test (send v1→v2, then jump straight to v3→v4, assert the presubmit still triggers) and a poison-config no-wedge test. Non-breaking. Bundles an unrelated drive-by fix to continueOnError handling in pjutil.FilterPresubmits — scope creep unrelated to #848. Currently failing the same two CI checks as #870; not yet lgtm'd.
