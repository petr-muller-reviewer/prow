# Triage

## Verdict

`accepted` — a reproducible build regression in this repository, already fixed by open PR #1056.

`pkg/config/zz_generated.deepcopy.go` imports `encoding/json/jsontext`, a package that Go 1.26 only exposes behind `goexperiment.jsonv2`, while `go.mod` declares `go 1.26.4`. The import leaked in when the file was regenerated with the dev toolchain (1.27.3, from `.go-version`), where `encoding/json.RawMessage` became an alias for `jsontext.Value`; `deepcopy-gen` printed the alias target. Any downstream module honoring the declared minimum fails to build `pkg/config` and everything importing it. PR #1056 pins `deepcopy-gen` to the `go` directive from `go.mod` and regenerates the file; CI is green.

## What the issue reports

- Building any package that imports `pkg/config` (reporter used `./cmd/crier`) on Go 1.26 fails: `build constraints exclude all Go files in .../encoding/json/jsontext`.
- The offending import is in generated code, `pkg/config/zz_generated.deepcopy.go`, not hand-written source.
- Generating that file with Go 1.27 pollutes it with a package only available in 1.27.
- Reporter proposes two fixes: run the generators under Go 1.26, or bump the version in `go.mod`.
- Reproduction given verbatim: `GOTOOLCHAIN=go1.26.4 go build ./cmd/crier`.

## Findings

### [reproducibility] failure reproduces on main with the declared minimum toolchain
- detail: `GOTOOLCHAIN=go1.26.4 go build ./cmd/crier` on HEAD `091a7d7` fails with the exact error from the report; the toolchain is downloaded automatically and the failure is in `pkg/config` import resolution.
- evidence: `package sigs.k8s.io/prow/cmd/crier / imports sigs.k8s.io/prow/pkg/config / imports encoding/json/jsontext: build constraints exclude all Go files in .../toolchain@v0.0.1-go1.26.4.linux-amd64/src/encoding/json/jsontext`

### [cause] deepcopy-gen built with Go 1.27 resolves the RawMessage alias and prints its target
- detail: In Go 1.27 `encoding/json.RawMessage` is `type RawMessage = jsontext.Value` (confirmed with `GOTOOLCHAIN=go1.27.3 go doc encoding/json.RawMessage`). `deepcopy-gen` uses the `go/types` of the toolchain it was compiled with and emits the resolved package path, producing `jsontext "encoding/json/jsontext"` and `new(jsontext.Value)`.
- evidence: `pkg/config/zz_generated.deepcopy.go:25,285`

### [cause] culprit commit regenerated the file with the 1.27 dev toolchain
- detail: Commit `4b994a5c2` ("chore: regenerate deepcopy code with go 1.27") changed only the import and the `new(...)` call, introducing the 1.27-only dependency into a module declaring `go 1.26.4`.
- evidence: `git show --stat 4b994a5c2` → `pkg/config/zz_generated.deepcopy.go | 4 ++--`

### [cause] the module minimum and the dev toolchain intentionally differ
- detail: `go.mod` declares `go 1.26.4` (raised by a dependency bump), while `.go-version` is `1.27.3` and `hack/build/setup-go.sh` installs that for generators and CI. Anything generated by the dev toolchain can therefore be newer than the module's promise.
- evidence: `go.mod:3`, `.go-version`, `hack/build/setup-go.sh:23`

### [related-code] source field that triggers the generated code
- where: `pkg/config/inrepoconfig.go:94`, `pkg/config/config.go:143`
- excerpt: |
    ProwIgnored *json.RawMessage `json:"prow_ignored,omitempty"`

### [related-code] generator invocation
- where: `hack/make-rules/update/codegen.sh:41-42,96-101`
- excerpt: |
    go build -o "${deepcopygen}" k8s.io/code-generator/cmd/deepcopy-gen
    ...
    "$deepcopygen" --output-file zz_generated.deepcopy.go \
      sigs.k8s.io/prow/pkg/apis/prowjobs/v1 sigs.k8s.io/prow/pkg/config

### [related-pr] open fix pins deepcopy-gen to the module's Go version
- ref: kubernetes-sigs/prow#1056
- relevance: Changes `codegen.sh` to derive `GOTOOLCHAIN` from the `go` directive in `go.mod`, builds and runs only `deepcopy-gen` with it, and regenerates `pkg/config/zz_generated.deepcopy.go` to `encoding/json` / `new(json.RawMessage)`. CI green; tide only waiting on `/approved`.

### [related-issue] downstream Prow bumps blocked by this breakage
- ref: openshift/ci-chat-bot#652, openshift/release-controller#838, openshift/ci-tools#5505, openshift/ci-tools-standalone#73
- relevance: All four open PRs are titled "Bump Prow to latest 52aea4401dc4" and cross-reference this issue; they cannot build until the generated import is fixed.

## Checked

- `go.mod` declares `go 1.26.4`; `.go-version` is `1.27.3` — the split is deliberate (dev/CI toolchain vs. consumer minimum), not a typo.
- `rg jsontext` finds exactly one occurrence in the tree (`pkg/config/zz_generated.deepcopy.go`); no other generated or hand-written file depends on it.
- `pkg/apis` contains no `json.RawMessage`/`jsontext` types, so only `pkg/config` output is affected.
- `hack/tools/go.mod` declares `go 1.26.3`; building `deepcopy-gen` with `GOTOOLCHAIN=go1.26.4` succeeds.
- Regenerated all deepcopy output with the 1.26.4-built generator: `pkg/apis/prowjobs/v1` is byte-identical, `pkg/config` differs only by `encoding/json` / `new(json.RawMessage)` — matching PR #1056's diff exactly.
- In Go 1.26, `encoding/json/jsontext` files carry `//go:build goexperiment.jsonv2`; in 1.27 the alias makes it unconditional.
- `verify-codegen` (`hack/make-rules/verify/codegen.sh`, run by `make verify`) regenerates with `.go-version` (1.27.3), so it reproduces the broken output and cannot catch this class of leak; no CI job builds with the `go.mod` minimum.
- Duplicate search queries (`jsontext`, `build constraints exclude`, `minimum go version`, `deepcopy go 1.27`, `Go version build`) found no other Prow issues on this topic.
